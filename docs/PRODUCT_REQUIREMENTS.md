# 제품 요구사항

이 문서는 목표와 인수 조건이다. 항목에 “해야 한다”가 있어도 구현 완료를 뜻하지
않는다. 2026-10-04 현재 상태는 [기능 대조표](BASIC_EDITOR_COVERAGE.md)와
[개발 계획](DEVELOPMENT_PLAN.md)을 따른다.
기존 에디터 대비 추가 목표는 [비교 분석](EDITOR_PARITY_AUDIT_2026-10-04.md)과
[보완 설계](EDITOR_PARITY_DESIGN.md)에 연결한다. 추가 요구사항은 미구현 계획이다.

## 1. 제품 비전

StarCraft UMS 제작자가 맵 편집기와 EUD 도구를 오가며 파일을 복사하고 오류 로그를 추적하는 부담을 줄인다. 하나의 Windows 데스크톱 앱에서 맵 데이터 편집, epScript 작성, 안전한 EUD 빌드와 결과 검증을 수행할 수 있게 한다.

제품의 핵심 가치는 기능 수보다 **맵을 손상시키지 않는 신뢰성**, **EUD 빌드의 재현성**, **문제가 난 지점을 찾을 수 있는 진단성**이다.

## 2. 대상 사용자

### 주요 사용자

- StarCraft: Remastered UMS 맵을 처음 제작하는 사용자
- ScmDraft/Chkdraft와 EUD 도구를 함께 사용하는 제작자
- epScript로 게임 로직을 작성하면서 맵 데이터도 자주 수정하는 개발자

### 사용자에게 기대하는 지식

- 파일과 폴더를 열고 저장할 수 있다.
- 일반 트리거 또는 epScript의 기본 개념을 배울 의향이 있다.
- 보호된 타인의 맵을 해제하거나 복구하는 기능을 기대하지 않는다.

## 3. 제품 원칙

1. **원본 우선:** 사용자의 명시적 선택 없이는 입력 맵을 덮어쓰지 않는다.
2. **무손실 우선:** 이해하지 못하는 데이터는 삭제하거나 재작성하지 않고 보존한다.
3. **명시적 빌드:** 프로젝트를 여는 것만으로 EUD 코드나 플러그인을 실행하지 않는다.
4. **진단 가능성:** 오류는 파일, 위치, 단계, 원시 로그와 함께 보여준다.
5. **점진적 기능:** 지원하지 않는 데이터는 읽기 전용으로 보여주더라도 맵 전체를 거부하지 않는다.
6. **도구 교체 가능성:** euddraft나 MPQ 구현을 UI와 분리한다.

## 4. 1차 지원 범위

### 플랫폼

- Windows 10/11 x64
- StarCraft: Remastered용 UMS 맵
- Flutter Windows 데스크톱 앱

### 맵 파일

- 보호되지 않은 `.scm` 및 `.scx`
- `staredit\scenario.chk` 읽기와 저장
- 알 수 없는 섹션과 원시 바이트 보존
- 원본을 건드리지 않는 Save As와 EUD 빌드 출력

### 편집 기능

- 맵 메타데이터와 크기 확인
- 지형 보기와 편집
- 유닛, 스프라이트/두다드, 로케이션 배치와 속성 편집
- 플레이어, 종족, 세력, 색상 설정
- 문자열 리소스 확인과 안전한 변경
- 일반 트리거 확인과 편집
- 실행 취소/다시 실행

기본 에디터 범위는 [기능 대조표](BASIC_EDITOR_COVERAGE.md)로 추적한다.
배치된 유닛 하나의 속성 편집과 맵 전체 유닛·업그레이드·테크 설정은 별도 기능이다.
새 맵 생성, 기본 등각 지형과 안개 편집, 문자열·사운드 관리, 미션 브리핑도
기본 제작 범위에 포함하며 구체적인 개발 순서는 M6.2~M7에서 관리한다.

### EUD 기능

- `.eps` 파일 편집
- euddraft 도구 경로 및 버전 확인
- 명시적인 Build 명령
- 입력 맵과 다른 출력 맵 생성
- 빌드 진행 상태, 경고, 오류, 원시 로그 표시
- 최근 성공 빌드 정보와 사용 도구 버전 기록
- 유닛·무기 EUD 확장 설정 UI와 생성 코드 미리보기, 선언적 설정 저장 및 명시적 빌드
- 업그레이드·테크·플레이어·그래픽의 검증된 EUD 확장 탭과 조건부 실행 규칙·동적 표현

## 5. 초기 범위에서 제외

- 보호/잠금된 맵 해제 또는 자동 복구
- StarCraft 실행 중 메모리 수정, 치트, 프로세스 주입
- Battle.net 자동 업로드나 배포
- macOS, Linux, Web, Android, iOS 정식 지원
- StarCraft 1.16.1과 Remastered를 동시에 만족하는 EUD 출력
- 완전한 epScript 언어 서버 또는 디버거
- 시각적 블록 기반 EUD 프로그래밍
- ScmDraft의 모든 고급 지형 브러시를 첫 릴리스에서 재현

## 6. 핵심 사용자 흐름

### 흐름 A: 기존 맵 안전하게 열기

1. 사용자가 `.scx`를 선택한다.
2. 앱이 파일을 읽기 전용으로 열고 구조와 크기를 검증한다.
3. 지원하지 않는 섹션과 경고를 요약한다.
4. 사용자는 맵을 탐색하고 지원되는 데이터를 편집한다.
5. Save As로 새 파일을 만든다.
6. 앱은 출력 파일을 다시 열어 기본 구조를 검증한다.

### 흐름 B: EUD 맵 빌드

1. 사용자가 기준 맵과 epScript 작업 폴더를 선택한다.
2. 앱이 euddraft 설치와 버전을 검사한다.
3. 사용자가 Build를 누른다.
4. 앱은 임시 폴더에서 빌드하고 로그와 진단을 수집한다.
5. 성공하면 새 `.scx`를 출력하고 원본이 바뀌지 않았음을 확인한다.
6. 실패하면 부분 출력물을 최종 결과로 노출하지 않고 오류 위치와 원시 로그를 보여준다.

### 흐름 C: 편집 오류 복구

1. 앱이 비정상 종료되거나 저장 검증에 실패한다.
2. 다음 실행에서 복구 가능한 자동 저장본을 발견한다.
3. 원본, 마지막 저장본, 자동 저장본을 구분해 보여준다.
4. 사용자가 복구본을 새 경로로 저장한다.

2026-10-03 [자동 저장·복구](AUTOSAVE_RECOVERY.md)를 구현했다. 기본 30초/5세대,
CHK·리소스·EUD 프로젝트·epScript 상태를 별도 앱 데이터에 보관하고 재실행에서
명시적으로 복원한다. 마지막 저장 맵이 변경/삭제되면 원본 MPQ 리소스를 추측하지
않고 복구를 거부한다. 미적용 폼 초안과 Undo 이력은 복구 범위 밖이다.

## 7. 기능 요구사항

### 문서와 작업 공간

- FR-001: 앱은 동시에 최소 한 개의 맵 문서를 열 수 있어야 한다.
- FR-002: 문서는 원본 경로, 현재 변경 여부, 마지막 저장/빌드 상태를 표시해야 한다.
- FR-003: 닫기 전에 저장되지 않은 변경을 명확히 알려야 한다.
- FR-004: 모든 편집 명령은 가능한 경우 실행 취소/다시 실행을 지원해야 한다.
- FR-005: 여러 맵을 탭으로 열고 문서별 dirty·Undo·초안·카메라·복구·빌드 상태를 분리해야 한다. 탭 전환과 비동기 결과가 다른 문서에 변경을 적용해서는 안 된다.

### 맵 입출력

- FR-101: 지원되는 맵에서 `scenario.chk`를 찾고 읽을 수 있어야 한다.
- FR-102: 섹션의 순서, 중복, 원시 페이로드를 보존할 수 있어야 한다.
- FR-103: 잘못된 길이와 파일 경계를 넘는 섹션을 오류로 보고해야 한다.
- FR-104: 저장은 임시 출력과 재검증을 거친 뒤 완료되어야 한다.
- FR-105: 지원하지 않는 맵을 저장 가능한 것처럼 표시해서는 안 된다.
- FR-106: 사용자는 지원 크기·타일셋과 초기 지형을 선택해 새 맵을 만들고 새 아카이브로 저장할 수 있어야 한다.
- FR-107: 검증된 저장/빌드 결과를 대상으로 SC:R 테스트 흐름과 결과 기록을 제공해야 한다. 직접 맵 실행 가능성을 먼저 조사하고 불가능하면 수동 선택을 지원한다. 게임 실행 성공과 맵 플레이 성공을 구분한다.

### 맵 편집

- FR-201: 캔버스는 이동, 확대/축소, 격자와 레이어 표시를 지원해야 한다.
- FR-202: 선택한 객체의 속성을 Inspector에서 편집할 수 있어야 한다.
- FR-203: 다중 선택과 삭제는 영향을 받는 객체 수를 보여줘야 한다.
- FR-204: 맵 경계 밖 배치와 잘못된 참조를 저장 전 검증해야 한다.
- FR-205: 사용자가 StarCraft: Remastered 설치 위치를 지정하면 앱은 로컬
  CASC에서 필수 타일셋 자산의 누락·무효 상태, 제품·빌드와 해결 방법을
  확인할 수 있어야 한다.
- FR-206: 맵 제목·설명, 플레이어 슬롯·종족·색상, 세력·이름·동맹·공동 승리·시작 위치 옵션을 편집할 수 있어야 한다.
- FR-207: 맵 전체 유닛 종류별 이름·능력치·생산 비용/시간·무기 피해량과 기본값 사용 여부를 편집할 수 있어야 한다.
- FR-208: 플레이어별 유닛 생산 허용과 기본값 상속을 편집할 수 있어야 한다. 현재 지원 범위는 [유닛 생산 허용](UNIT_AVAILABILITY.md)을 따른다.
- FR-209: 업그레이드 비용/시간·증가량 및 플레이어별 시작/최대 레벨과 기본값을 편집할 수 있어야 한다. 현재 지원 범위는 [업그레이드 설정](UPGRADE_SETTINGS.md)을 따른다.
- FR-210: 테크 연구/사용 설정과 플레이어별 허용·연구 완료·기본값을 편집할 수 있어야 한다. 현재 지원 범위는 [테크 설정](TECH_SETTINGS.md)을 따른다.
- FR-211: 시작 위치와 배치된 유닛의 지원 상태·연결 관계, 다중 공통 속성을 검증해서 편집할 수 있어야 한다.
  2026-10-01 시작 위치·상태/valid flags·Addon/Nydus·일괄 속성을 구현했다.
  Sprite/Doodad 상태 및 안전한 편집 범위는 [기본 편집 도구](BASIC_EDITING_TOOLS.md)를 따른다.
- FR-212: 기본 등각 지형·경사로와 플레이어별 초기 안개를 편집할 수 있어야 한다. raw 타일 편집과 구분한다.
  2026-10-01 평지 전체 채우기·ISOM/TILE/MTXM 동기화·미리보기/Undo까지 구현했다.
  초기 안개 브러시·사각형·전체 채우기도 구현했다. [전환 연결표·수직 적층 재계산](ISOM_TRANSITIONS.md)으로 기존 ISOM의 타일 재계산을 지원한다.
  [새 경계 자동 연결·높이/경사로·등각 선택 영역 브러시와 시각 미리보기](ISOM_BRUSHES.md)를 구현했다. 실제 게임/외부 에디터 인수는 별도다.
  [지형 계약](ISOMETRIC_TERRAIN.md), [기본 편집 도구](BASIC_EDITING_TOOLS.md).
- FR-213: 같은 문서의 지형·객체 영역을 자르기/복사/붙여넣기하고 서로 다른 편집을 문서의 시간순으로 Undo/Redo할 수 있어야 한다.
  Raw MTXM·유닛/Sprite/로케이션·검증된 단일 Doodad clipboard와 공통 기록을 구현했다.
  문서 간 clipboard와 다수 Doodad 혼합 선택은 지원하지 않는다.
- FR-214: 맵 크기 변경은 잘리는 데이터와 좌표 변화의 영향을 보여준 뒤 명시적 적용과 Undo를 지원해야 한다.
- FR-215: 미니맵 탐색, 로케이션 목록·고도 조건 편집과 겹친 객체 선택을 지원해야 한다.
  객체 이름/종류 ID·레이어/소유자 검색과 전체/반전/관련 선택, 좌표 이동·선택 범위 맞춤을 제공한다([구현 계약](SELECTION_NAVIGATION.md)).
  미니맵 클릭/드래그, 로케이션 이름/ID 검색·고도 일괄 적용과 Alt 클릭 순환을 구현했다.
- FR-216: 문자열·사운드의 검색·사용처·안전한 변경과 사운드 가져오기/추출/재생을 지원해야 한다. 참조를 알 수 없으면 삭제를 제한한다.
- FR-217: 유닛·pure sprite·unit-sprite·두다드를 그림/이름/종류 ID로 구분하고 검증된 유형의 배치·footprint 미리보기·실패 이유·Undo를 제공해야 한다. 아직 미지원인 유형은 선택 전에 사유를 표시한다.
- FR-218: 격자 표시와 객체 스냅을 별도로 설정하고 건물/유닛 정렬·정상/자유 배치 정책을 구분해야 한다. 자유 배치가 구조·경계·참조·두다드 안전 검증을 해제해서는 안 된다.
- FR-219: 검증 자료가 있는 높이·건설/이동 가능성·범위/전력/크립 보조 표시를 읽기 전용으로 제공해야 한다. 미확인 자료와 게임 동작 보증 여부를 구분한다.
- FR-220: raw/ISOM 사용자 브러시 저장·재사용과 검증된 지형 대칭을 지원해야 한다. 타일셋·자료 revision·경계를 검증하고 대응 자료 없는 ramp/두다드를 추측 변환하지 않는다.
- FR-221: 다수 두다드와 객체·지형의 혼합 선택을 복사하고 지원된 ISOM 경계를 재검증해야 한다. 부분 footprint·불명확한 overlay/관계는 거부하고 한 번의 Undo로 복원한다.
- FR-222: 지원 프로필 안에서 문서 간 복사를 제공하고 문자열·로케이션·사운드·class ID·연결을 명시적으로 재매핑해야 한다. 참조/용량/타일셋 검증 실패 시 전체 무변경이어야 한다.
- FR-223: 일반 유닛/무기·업그레이드·테크 설정의 검증된 로컬 DAT 기본 수치와 CHK override·상속·예상값을 구분해야 한다. 조회 실패를 0이나 기본값으로 표시하지 않는다.
- FR-224: 검증된 CRGB 색상 모드와 RGB·COLR 우선순위를 안전하게 편집하고 캔버스 미리보기에 반영해야 한다. 알 수 없는 모드·중복/손상은 원시 보존한다.
- FR-225: 게임 문자열 색상/제어 token 선택과 읽기 전용 미리보기를 제공해야 한다. 알 수 없는 바이트와 공유 문자열 참조를 보존하며 영향 미리보기 후 명시적으로 적용한다.
- FR-226: 사운드의 탐지/미리보기/가져오기 지원표와 로컬 게임 사운드 선택을 제공해야 한다. 추가 codec은 라이선스·크기 상한·게임 재생을 검증한 뒤 허용한다.
- FR-227: 맵 전체/영역·레이어의 이미지 출력을 크기 상한과 별도 경로로 제공해야 한다. 게임 자산 배포 경계를 확인하고 문서/카메라 상태를 변경하지 않는다.

### 일반 트리거와 브리핑

- FR-401: 기본 트리거 조건·액션의 지원 목록과 인자 편집, 복제·순서·소유자·활성 상태 변경을 제공해야 한다.
- FR-402: 스위치, 유닛 생성 속성 슬롯, 문자열·로케이션·사운드 참조를 함께 검증해야 한다.
- FR-403: 미션 브리핑의 텍스트·초상화·소리·시간·순서를 편집할 수 있어야 한다. 구현 범위와 실제 게임 확인은 [미션 브리핑 편집기](BRIEFING_EDITOR.md)를 따른다.
- FR-404: 미지원/EUD 트리거의 원시 바이트를 보존하고 일반 편집기가 임의로 재작성해서는 안 된다.
- FR-405: 일반 트리거의 소유자·활성·조건/액션·문자열/로케이션 참조를 검색/필터하고 지원된 선택 범위의 일괄 변경을 미리보기·원자적 Apply·Undo로 처리해야 한다.
- FR-406: EUD 빌드 없이 제한된 일반 트리거 스크립트를 TRIG로 파싱/생성하고 GUI와 왕복 편집해야 한다. 미지원/EUD 원시 기록을 보존하고 언어 실행 없이 검증해야 한다.

### EUD

- FR-301: euddraft 실행 파일/환경을 사용자 설정으로 지정할 수 있어야 한다.
- FR-302: 빌드 명령은 셸 문자열 결합이 아닌 인자 목록으로 실행해야 한다.
- FR-303: 도구 버전, 시작/종료 시각, 종료 코드, 로그를 기록해야 한다.
- FR-304: 프로젝트를 여는 행위만으로 EUD 코드를 실행해서는 안 된다.
- FR-305: 빌드 출력은 기준 맵과 다른 경로에 생성해야 한다.
- FR-306: 오류 위치를 파악하지 못하더라도 원시 로그 전체에 접근할 수 있어야 한다.
- FR-307: 유닛 설정에서 일반 CHK 항목과 EUD 확장 항목을 구분하고 사거리·실드 활성 여부·피해 유형을 설정할 수 있어야 한다.
- FR-308: 무기 선택·공격 대상·공격 주기·스플래시와 후속 속성은 필드별 지원 매니페스트 및 도구/게임 검증을 통과한 범위만 제공해야 한다.
- FR-309: 공유 무기/이동 데이터의 영향 범위와 일반 설정·EUD override 충돌을 표시하고, 종류별 전역 설정을 개별 유닛 설정으로 오인하게 해서는 안 된다.
- FR-310: 선언적 EUD 설정을 프로젝트로 저장·재열기·Undo/Redo하고 일반 맵 저장과 EUD 빌드의 적용 차이 및 빌드 최신 여부를 보여줘야 한다.
- FR-311: 생성 코드는 사용자 소스를 보존하고 명시적 Build로만 새 맵에 반영해야 한다. 반복 빌드가 패치를 누적하거나 기존 EUD를 추측해 재작성해서는 안 된다.
- FR-312: 지원 category가 있는 설정 화면은 공통 EUD 확장 탭을 제공하며 동일 필드를 한 프로젝트 항목으로 공유해야 한다.
- FR-313: 업그레이드·테크 metadata와 플레이어 인구수 등 검증된 확장 필드를 제공하고 일반 설정/액션과 구분해야 한다.
- FR-314: Sprite/Image의 검증된 참조·표시 속성을 설정하고 공유 영향과 classic/HD 지원 여부를 보여줘야 한다.
- FR-315: 필드별 대상 영역·시점·자료형·호환성과 검증 증거를 관리하고 탭 간 충돌·중복 생성을 차단해야 한다.
- FR-316: EUD 실행 규칙은 타입 있는 조건/값/대상/주기를 편집하고 기본 트리거로 표현 가능한 항목은 기본 경로를 우선해야 한다.
- FR-317: 런타임 개체·계산된 로케이션·동적 텍스트를 지원할 때 개체 수명, 참조·실행 비용과 원본 프로젝트 보존을 검증해야 한다.
- FR-318: 클라이언트 표시와 동기화 게임 상태 변경을 분리하며 지원 규칙을 실제 게임과 멀티플레이에서 검증해야 한다.
- FR-319: epScript/Python/Lua의 검증된 제한 문법을 공통 모델로 작성/전환하고 일반/EUD 모드를 구분해야 한다. 임의 코드 번역은 지원하지 않으며 authored native EPS/Python은 원본으로 보존한다. [언어 계획 L0~L6](EUD_TOOLCHAIN_LANGUAGE_PLAN.md)을 따른다.
- FR-320: 프로젝트 루트 안의 여러 소스를 탐색·편집하고 언어별 색상/정적 완성·검색·원본 file:line 진단 이동을 제공해야 한다. 열기/완성만으로 코드를 실행하지 않고 루트 밖 경로/외부 변경을 검증해야 한다.

## 8. 비기능 요구사항

- NFR-001: 256×256 맵의 기본 탐색이 일반적인 개발용 PC에서 끊김 없이 동작해야 한다.
- NFR-002: 대용량 파싱, 저장, 빌드는 UI 스레드를 막지 않아야 한다.
- NFR-003: 동일 입력과 동일 도구 버전의 빌드는 재현 가능한 결과를 목표로 한다.
- NFR-004: 파서 오류에는 바이트 오프셋과 섹션 식별자가 포함되어야 한다.
- NFR-005: 로그에 사용자 파일 내용이나 개인 경로를 불필요하게 수집하지 않는다.
- NFR-006: 외부 도구가 없어도 맵 편집 기능의 핵심 테스트를 실행할 수 있어야 한다.
- NFR-007: 새 의존성은 유지보수 상태, 라이선스, 배포 크기를 검토한 뒤 추가한다.
- NFR-008: 핵심 제작 과제는 키보드 focus·고대비·지원 DPI/화면에서 조작 가능하고 처음 제작자의 관찰 테스트를 통과해야 한다. 테스트 범위와 발견 문제를 기록한다.
- NFR-009: 다중 문서/보조 표시의 총 자산 캐시 예산·취소/수명 경계를 유지하고 대표 맵의 profile 성능과 반복 작업 메모리를 측정해야 한다. debug 스모크 결과를 실제 FPS나 누수 부재로 표시하지 않는다.

## 9. MVP 정의

MVP는 다음 수직 흐름이 모두 실제 파일로 검증된 상태다.

이 MVP는 안전한 입출력과 EUD 빌드의 최소 검증 기준이다. 기본 맵 에디터 전체가
완성됐다는 기준으로 사용하지 않는다. 기본 에디터 완료에는 M6.2~M7의 기본
기능과 M8의 품질 게이트 및 [기능 대조표](BASIC_EDITOR_COVERAGE.md)의 제작
시나리오 검증이 추가로 필요하다.

1. 보호되지 않은 테스트 `.scx`를 연다.
2. 맵 요약과 최소 한 종류의 편집 가능한 데이터를 표시한다.
3. 원본에 손대지 않고 Save As로 새 맵을 만든다.
4. epScript를 편집하고 euddraft로 별도 출력 맵을 빌드한다.
5. 실패와 성공 로그를 앱에서 확인한다.
6. 출력 맵을 다시 열어 구조 검증을 통과한다.
7. 자동화 테스트와 수동 StarCraft 실행 스모크 테스트를 통과한다.

## 10. 성공 지표

- 저장 및 EUD 빌드 과정에서 원본 맵이 변경된 사례 0건
- 공식 테스트 픽스처의 알 수 없는 CHK 데이터 보존율 100%
- 지원 맵의 열기 → Save As → 다시 열기 성공률 100%
- 파악 가능한 빌드 오류의 파일/행 표시율 향상
- 릴리스 빌드에서 치명적 오류 발생 시 복구 가능한 로그 제공

## 11. 미결정 사항

2026-10-04 다중 맵/언어/게임 테스트의 제품 범위는 위 FR와 EP 계획으로 구체화했다.
아래 항목은 필요 여부가 아니라 구현 정책/호환 범위의 미결정이다.

- 새 도구 버전의 검토·배포 및 프로젝트 마이그레이션 정책
- 다중 언어 entry와 소스 파일 관리 범위
- 다중 맵·다중 소스 문서의 후속 지원 범위
- StarCraft 실행 경로 자동 탐색과 테스트 실행 범위

euddraft 동봉은 [ADR-0011](decisions/0011-managed-euddraft-bundle.md),
EUD JSON 프로젝트는 [ADR-0009](decisions/0009-declarative-eud-project.md)와
[실행 규칙 schema v2/v3](EUD_EXECUTION_RULES.md)로 구현했다.
StormLib 연동은 [별도 helper 프로세스](decisions/0004-stormlib-helper-process.md)로 결정했다.
