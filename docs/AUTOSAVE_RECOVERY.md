# 자동 저장과 미저장 작업 복구

2026-10-19 [다중 소스 복구](SOURCE_WORKSPACE.md)는 schema v3에 모든 탭의
원문/저장 기준·루트·활성 탭을 포함한다. 단순 탭 전환으로 복구 세대 소유권을
나누지 않는다. 복구 후 파일/코드를 자동 실행하거나 쓰지 않으며 루트를 새로
고치기 전에는 프로젝트 파일 저장/빌드를 허용하지 않는다. 전체 Undo 이력은 복구하지 않는다.

2026-10-19: [미적용 트리거 초안 복구](EUD_SOURCE_TRANSLATION_RECOVERY.md)를
schema v2에 추가했다. 현재 코드·언어·미저장 원문 이력·정확한 CHK 기준을
문서별로 checkpoint하며 명시 복구 후에도 자동 적용하지 않는다. 별도 프로세스의
검증 완료 checkpoint 후 강제 종료/재시작과 partial 제외를 검증했다. 전원 차단
전체 행렬과 마지막 checkpoint 이전 입력 무손실을 확인한 것은 아니다.

2026-10-16 여러 맵의 각 문서는 독립 AutosaveController/owner·보관 목록·타이머를
가진다. 복구는 별도 새 문서에 하며 열린 다른 문서 소유 체크포인트의 복구/삭제와
열린 원본 경로 중복을 거부한다. 원본 덮어쓰기·자동 복원은 여전히 하지 않는다.
initialize는 중복 호출해도 timer를 중복 생성하지 않는다. [여러 맵 계약](MULTI_MAP_WORKSPACE.md).

2026-10-03 구현. [개발 계획](DEVELOPMENT_PLAN.md) M8의 자동 저장·충돌 복구 항목을 담당한다.
손상/보호 맵 복구나 외부 편집 내용 병합은 제공하지 않는다.

## 사용자 흐름

- 기본 30초 간격으로 미저장 작업의 복구본을 만든다. 창이 비활성화될 때에도 체크포인트를 요청한다.
- File → 자동 저장 설정에서 켜기/끄기, 5~600초 간격, 작업 공간별 1~20개 보관을 설정한다. 기본 보관 수는 5개다.
- 다음 실행에서 복구본이 있으면 목록을 표시한다. 나중에는 File → 미저장 작업 복구로 다시 연다.
- 목록은 자동 저장 시각, 마지막 저장 맵, EUD 프로젝트와 epScript 경로를 구분한다.
- 복구본 열기는 검증 후 메모리 문서를 복원한다. 맵은 기존 Save As로 새 경로에 저장한다.
- 복원한 EUD 프로젝트는 새 미저장 프로젝트로 열어 Save Project As를 요구한다. 원래 프로젝트 파일을 덮어쓰지 않는다.
- 미저장 문서나 진행 중 작업이 있으면 복구를 거부한다. 복구본 삭제는 명시적 확인이 필요하다.

## 보관 계약

저장 위치는 `%LOCALAPPDATA%/blackvrice/StarCraftMapEditor/recovery`다.
각 실행은 시간·난수로 독립된 ID를 사용한다. 최신 세대 생성 → flush → 재읽기·검증 →
새 파일명으로 rename 이후에만 해당 작업 공간의 이전 세대를 보관 수에 맞춰 지운다.
이전 실행/다른 창의 복구본은 자동 정리하지 않고 목록에서 사용자가 삭제한다.
선택하여 복원한 세대는 현재 작업 공간에 편입하며 저장/변경 취소 후 clean 상태의
다음 체크포인트에서 정리한다. 정상 종료도 미저장 복구본을 유지한다.

schema 1 JSON에는 다음 정보를 기록한다.

- 마지막 저장 CHK 바이트와 현재 CHK 전체 바이트, 편집된 섹션 인덱스
- 원본 맵 경로·크기·UTC 수정 시각·SHA-256 fingerprint
- 추가/교체한 PCM WAV 바이트와 삭제 tombstone
- 선언적 EUD 프로젝트 JSON, 기존 프로젝트 경로(표시용)
- epScript 파일명·경로·마지막 저장 텍스트·현재 텍스트

섹션 순서·중복·알 수 없는 payload·원시 문자열은 인코딩된 그대로 보존한다.
복구 중 dirty 인덱스를 다시 적용하여 편집된 TRIG/MBRF의 기존 저장 전 검증도 유지한다.
브러시 transaction, 활성 파일/빌드 작업, EUD 프로젝트 I/O 중에는 체크포인트를 건너뛴다.
타이머 요청은 단일 쓰기로 직렬화하며 저장 중 새 편집은 다음 체크포인트에 포함한다.
미적용 설정/트리거 대화상자 초안, 캔버스 선택/카메라, Undo/Redo 이력은 보관하지 않는다.
복구된 문서는 새로운 편집 이력에서 시작한다.

## 검증과 안전

복구 파일은 원본/배포용 맵이 아니다. 파일 envelope에 본문 SHA-256을 포함하며
이는 우발적 손상 검출이지 작성자 인증이 아니다. 전체 파일은 192 MiB 이하,
리소스 변경은 512개 이하로 제한한다. WAV는 기존 경로/PCM 검증을 통과해야 한다.
직렬화·파일 읽기·해시·복구본 디코딩은 별도 isolate에서 수행한다.
CHK는 기존 파서·typed view·참조 검증으로 확인한다.

`.partial` 파일은 복구 목록에 포함하지 않는다. 쓰기·검증 실패는 이전 정상 세대를
유지하고 UI에 오류를 표시한다. 손상된 완성 파일은 손상 항목으로 목록에 남긴다.
파일 ID의 경로 순회, 링크와 링크를 통과하는 저장 디렉터리를 거부한다.
게임 원시 자산·렌더링 이미지는 포함하지 않으며 복구 시 외부 코드를 실행하지 않는다.

기존 맵의 다른 MPQ 항목은 원본 아카이브에 유지한다. 복구 시 원본 fingerprint를
읽기 전후 확인하고 마지막 CHK와 정확히 비교한다. **마지막 저장 맵이 삭제·변경되면
복구를 중단하고 복구본을 유지한다.** 외부 변경을 자동 병합하거나 새 아카이브에서
누락 리소스를 추측하지 않는다. 새 맵은 원본 없이 복구 가능하다.
최종 Save As는 기존 임시 MPQ 출력·재열기·바이트/리소스 검증·원자적 승격을 따른다.

## 검증 기록

- 컨트롤러: 새 맵·중복/알 수 없는 CHK·WAV 추가/삭제·EUD/epScript 재시작 복구,
  외부 fingerprint 충돌·손상·기존 미저장 문서 거부, 실패 시 이전 세대 보존,
  쓰기 직렬화·transaction 건너뛰기·보관 수·clean 정리 검증.
- 파일 시스템: 실제 임시 폴더 재시작·체크섬 손상·부분 파일 제외·경로 순회·기존 파일 보호 검증.
- UI: 한국어 복구 목록·삭제 취소·복구 실행·좁은 화면·자동 저장 설정 저장 검증.
- 자체 제작 MPQ: 기존 맵 편집 → 디스크 복구본 → 새 컨트롤러에서 복구 → Save As →
  재열기, CHK·WAV 바이트와 원본 전체 바이트 보존 검증.
