# 데이터 안전과 보안

## 1. 보호 대상

- 사용자의 원본 `.scm`/`.scx`
- epScript와 플러그인 소스
- 자동 저장 및 빌드 결과
- 로컬 설치 경로와 사용자 이름 같은 개인정보
- 앱이 실행할 수 있는 외부 프로세스 권한

## 2. 위협 모델

맵과 EUD 프로젝트는 신뢰할 수 없는 입력일 수 있다.

- 조작된 길이로 메모리/디스크 자원을 과다 사용
- 비정상 MPQ/CHK로 파서 크래시 유도
- 경로 순회를 통한 작업 폴더 밖 파일 접근
- Python 플러그인이나 빌드 스크립트에서 임의 코드 실행
- 심볼릭 링크 또는 경로 충돌로 원본 덮어쓰기
- 로그를 통한 개인 경로와 환경 변수 노출
- 성공처럼 보이는 손상된 부분 출력

이 앱은 맵 보호 해제 도구나 악성 파일 분석 sandbox가 아니다.

## 3. 원본 맵 보호

- 기본 저장은 Save As
- 빌드는 입력과 다른 출력 경로 강제
- 작업 시작과 완료 시 입력 fingerprint 비교
- 최종 파일은 임시 파일을 검증한 뒤 승격
- 출력 경로가 입력과 같은 실제 경로인지 정규화 후 비교
- 기존 출력 파일 교체 전 사용자 확인과 복구 가능한 백업
- 앱 크래시 후 임시 파일을 자동으로 원본에 덮어쓰지 않음

현재 fingerprint는 파일 크기, UTC 수정 시각과 SHA-256으로 구성한다. 해시
계산 전후 파일 종류·크기·수정 시각이 같아야 유효한 값으로 인정한다. Open
Map은 helper 호출 전후 값을 비교하고, Save As는 세션에 저장한 값과 작업 시작
값을 비교한 뒤 최종 승격 직전에 다시 확인한다. 불일치, 삭제, 읽기 실패 또는
계산 중 변경은 작업을 실패시키며 기존 세션과 원본을 유지한다.

### EUD 빌드 설정 경계

`EudBuildConfiguration`은 빌드 시작 전에 기준 맵, 소스 루트, 진입 소스와
출력 맵을 Windows 절대 경로로 고정한다. 출력은 기준 맵과 같은 경로일 수 없고
소스 트리 밖에 있어야 하며, 진입 소스는 소스 루트 안에 있어야 한다. 대소문자와
경로 구분자 차이로 이 규칙을 우회하지 못하도록 비교용 경로를 정규화하고,
장치 경로, 예약 장치 이름, 상위 경로 세그먼트와 Windows에서 모호한 바깥
공백·끝 공백·점을 거부한다.

이 모델은 파일 시스템을 읽지 않으므로 존재 여부, symbolic link와 canonical
경로 동일성까지 보장하지 않는다. 후속 빌드 파이프라인은 입력 fingerprint를
기록하고 실행·승격 직전에 실제 경로 동일성과 파일 종류를 다시 확인해야 한다.

### epScript 미저장 변경

epScript dirty 상태는 현재 텍스트와 마지막 저장 기준선의 차이로 계산한다.
같은 내용으로 되돌리면 자동으로 Clean이 되며, dirty 문서는 명시적 discard
승인 없이는 다른 소스로 교체하거나 닫지 않는다. 현재 UI의 새 `main.eps`는
`In-memory draft`로 표시하고 실제 파일을 썼다고 표시하지 않는다. 후속 파일
저장은 외부 변경 검사와 검증된 쓰기가 성공한 뒤에만 저장 기준선을 갱신한다.

### 지형 편집 경계

- 편집은 정확히 하나의 유효한 격자형 `MTXM`이 있는 제한되지 않은 세션에만
  허용한다. 중복/손상 `MTXM`이나 euddraft 보호 마커를 임의로 고르지 않는다.
- 선택과 미리보기는 문서를 변경하지 않는다. Brush와 Rectangle 적용 때에만
  대상 `MTXM` payload의 같은 위치 `u16` 값을 교체하고 길이를 유지한다.
- `TILE`, 정상 `ISOM`, 미지원 섹션, 중복 섹션의 순서와 raw payload는
  자동 변환하거나 정규화하지 않는다.
- 편집은 메모리 세션만 dirty로 만들며 원본 아카이브에 직접 쓰지 않는다.
  Save As의 임시 출력·재열기·byte 검증·승격 계약을 그대로 통과해야 한다.
- 현재 UI는 게임 지형 `MTXM`과 외부 에디터용 지형 표현을 동기화하지 않음을
  명시한다. ISOM 재생성 규칙을 모르는 상태에서 그럴듯한 값을 만들지 않는다.

## 4. 바이너리 입력 방어

- 모든 길이와 개수에 상한 적용
- 덧셈/곱셈 overflow를 검사한 뒤 버퍼 접근
- 파일 범위를 벗어나는 섹션 즉시 중단
- 오류 메시지 생성 중에도 원시 페이로드를 무제한 출력하지 않음
- 파싱을 UI isolate와 분리
- fuzz와 손상 픽스처를 회귀 테스트로 유지

상한을 넘는 정상 파일 가능성이 있다면 “손상”으로 단정하지 않고 제한값과 해결 방법을 보여준다.

## 5. 외부 프로세스

- 사용자가 Build/Test를 눌렀을 때만 실행
- 셸 명령 문자열을 만들지 않고 인자 목록 사용
- 현재 사용자와 같은 권한으로 실행
- 실행 파일과 작업 디렉터리를 UI에서 확인 가능
- 환경 변수는 필요한 값만 전달
- timeout과 취소 경로 제공
- 프로세스 트리 종료 정책을 검증
- 종료 코드와 출력 검증이 끝나기 전 성공 표시 금지

Python 플러그인은 파일 접근과 네트워크 접근이 가능한 임의 코드로 간주한다.

### StarCraft 데이터 자산

- 저장소와 배포 패키지에 StarCraft 게임 데이터 파일을 포함하지 않는다.
- 앱은 사용자가 명시적으로 선택한 절대 StarCraft: Remastered 설치 경로의
  로컬 CASC 저장소만 읽기 전용으로 검사하고 타일 이미지를 합성한다.
- pinned CascLib을 정적으로 링크한 번들 helper는 별도 프로세스에서 실행한다.
  셸, `PATH` 검색, 온라인 CASC와 부모 환경 전체 상속을 사용하지 않는다.
- 각 필수 자산은 `CASC_STRICT_DATA_CHECK`로 끝까지 읽는다. 개별 자산 64 MiB,
  전체 256 MiB와 stdout/stderr 각 256 KiB 상한을 적용한다. 설치 검사는 기본
  15초, 타일 아틀라스 합성은 기본 30초 timeout을 적용한다.
- 선택한 자산을 앱 데이터, 프로젝트 또는 맵 파일로 복사·추출하지 않으며
  인터넷에서 다운로드하지 않는다. CASC 파일이나 인덱스를 수정하지 않는다.
- [ADR-0006](decisions/0006-request-scoped-tile-atlas-cache.md)의 타일 렌더링은
  원시 자산 대신 최대 4,096개의 정규화된 32×32 RGBA만 앱 소유 요청별
  임시 파일로 전달한다. binary envelope는 17 MiB로 제한하고 이미지 생성
  직후 삭제하며 디스크 영구 캐시는 만들지 않는다.
- 알 수 없는 자산의 이름·내용을 변경하거나 손상된 저장소를 추측해 복구하지
  않는다. 복구가 필요하면 Battle.net Scan and Repair를 안내한다.
- 설치 경로는 로컬 사용자 설정에만 저장한다. 진단 공유 시 개인 경로가 포함될
  수 있으므로 UI 메시지와 원시 상세 정보를 분리한다.
- 자산 누락은 실제 타일 이미지 기능만 제한하며 맵 원본 보호와 Save As
  파이프라인의 성공 조건을 변경하지 않는다.

### euddraft 설치 검사

- 설치 검사는 `euddraft.exe`를 실행하지 않고 파일 시스템 메타데이터와
  `VERSION`만 읽는다.
- 프로젝트, 사용자 설정, 번들 후보 중 선택된 절대 경로만 사용하며 `PATH`
  검색과 자동 다운로드를 하지 않는다.
- 상위 우선순위 경로가 잘못되어도 다른 설치로 자동 우회하지 않는다.
- `VERSION`은 최대 64바이트의 4성분 숫자만 허용하고 검증된 exact version
  allowlist와 비교한다.
- 실행 파일, Python 런타임, eudplib/epScript companion과 라이선스 파일은
  0바이트가 아닌 일반 파일이어야 하며 symbolic link는 인정하지 않는다.

### euddraft 프로세스 실행

- 검사된 절대 실행 파일을 `runInShell=false`로 실행하며 `PATH`로 도구를
  다시 찾지 않는다.
- 절대 경로의 비어 있지 않은 일반 `.eds` 파일만 단발 빌드 입력으로 허용한다.
  장기 실행 `.edd`와 보호 모드 `.scx`는 이 어댑터에서 실행하지 않는다.
- 설정 파일 부모를 명시적 작업 디렉터리로 사용하고 stdin은 즉시 닫아
  예상하지 못한 대화형 입력 대기를 막는다.
- 부모 프로세스 환경 전체를 상속하지 않는다. Windows 실행에 필요한
  allowlist와 사용자가 빌드에서 명시한 override만 전달하며 환경 전체를
  로그에 기록하지 않는다.
- stdout/stderr는 동시에 소비하고 스트림별 기본 1 MiB를 넘으면 초과분을
  보관하지 않은 채 끝까지 비운 뒤 빌드를 실패시킨다.
- timeout, Build 취소와 스트림 구독 취소는 해당 스트림이 소유한 프로세스만
  종료한다. 종료 코드 0만으로 최종 맵 성공을 선언하지 않는다.
- 공식 euddraft는 자체 업데이트 검사를 수행할 수 있으므로 빌드 직전에
  설치·버전을 다시 검사하고 사용자에게 외부 도구의 네트워크/쓰기 가능성을
  알린다. 앱 자체는 도구를 자동 다운로드하거나 교체하지 않는다.

### MPQ archive helper

StormLib 연동 helper는
[ADR-0004](decisions/0004-stormlib-helper-process.md)의 프로세스 경계를
따른다.

- 패키지에 포함된 helper의 절대 경로만 사용하고 `PATH` 검색과 셸 실행을
  허용하지 않는다.
- 사용자 경로와 요청 데이터는 명령줄이 아니라 버전이 있는 JSON stdin으로
  전달한다.
- stdout은 구조화 프로토콜 전용, stderr는 제한된 로그 전용으로 사용하고
  두 스트림을 동시에 소비한다.
- helper가 접근할 수 있는 MPQ 항목은 MVP에서 정확히
  `staredit\scenario.chk`로 제한한다.
- 원본과 임시 출력의 실제 경로가 같으면 거부하며 helper는 원본을 제자리
  수정하지 않는다.
- 입력, CHK, 임시 출력은 앱이 만든 요청별 임시 디렉터리와 명시된 절대
  경로만 사용한다. 바이너리를 로그나 JSON에 포함하지 않는다.
- 종료 코드와 최종 응답뿐 아니라 앱의 CHK 파싱, 임시 출력 재열기와 byte-exact
  CHK 검증이 모두 성공한 뒤에만 최종 출력으로 승격한다. 또한 저장 시작과
  승격 직전 입력 fingerprint가 열린 세션과 같아야 한다.
- timeout, 취소, 크래시 때 프로세스 트리를 종료하고 앱이 만든 정확한 요청
  임시 디렉터리만 정리한다.

현재 archive helper 구현은 다음 상한과 검증을 적용한다.

- 줄바꿈으로 끝나는 단일 JSON stdin 레코드 최대 64 KiB
- stdout/stderr 캡처 각각 최대 1 MiB, 초과분은 메모리에 보관하지 않고 계속 소비
- 추출 `scenario.chk` 기본 최대 64 MiB
- 아카이브 응답 목록 최대 1,024개, 동일 block index는 한 번만 노출
- `protocolVersion`, request ID, 작업, helper/StormLib 버전의 완전 일치
- helper 작업 디렉터리와 동일한 기존 디렉터리 안의 새 CHK 입출력과 임시 MPQ
  출력만 허용
- 원본 아카이브 read-only 추출, 원본을 복사한 뒤 복사본만 수정하는 교체,
  기존 임시 출력 덮어쓰기 거부
- StormLib 전체/열거 항목 수와 목록 완전성, MPQ version, uint32 크기·flags·
  locale, 선택한 locale의 `scenario.chk` 목록/추출 메타데이터와 Dart에서
  읽은 바이트 길이의 일치
- listfile 없는 합성 이름은 진단 표시로만 사용하고 원본 경로나 저장 대상
  이름으로 추측하지 않음

현재 Save As는 교체 확인 여부와 무관하게 열린 원본과 같은 실제 경로를
거부한다. 다른 기존 최종 경로는 Windows `OFN_OVERWRITEPROMPT`에서 사용자가
명시적으로 승인한 경우에만 교체할 수 있다. 앱은 기존 출력의 fingerprint도
작업 시작과 승격 직전에 비교하므로, 승인 뒤 파일이 변경·삭제되거나 처음에는
없던 파일이 생기면 승격하지 않는다.

교체가 승인된 기존 출력은 최종 경로의 같은 디렉터리에
`<파일명>.backup-<고유 작업 ID>.bak` 형식으로 이동한다. 그 뒤에만 검증된
임시 맵을 최종 경로로 rename한다. 승격이 실패하면 백업을 원래 경로로 자동
복원한다. 자동 복원도 실패하면 백업은 임시 작업 공간 밖에 그대로 보존하고
`SAVE_MAP_PROMOTION_RECOVERY_REQUIRED` 진단에 백업과 복원 대상 경로를
표시한다. 성공한 교체의 백업도 자동 삭제하지 않으며 사용자가 새 맵을 확인한
뒤 직접 정리한다.

원본이나 기존 출력의 검증 실패는 임시 작업 공간만 정리한다. 백업은 앱 소유
임시 작업 공간에 포함하지 않아 일반 cleanup이나 다음 실행이 삭제하지 않는다.

### EUD 빌드 출력

EUD 빌드도 최종 출력과 같은 디렉터리에 앱 소유 형제 작업 공간을 만들고
euddraft의 `output`을 그 안의 `temporary-output.scx`로 제한한다. 빌드
시작 전 기준 맵과 진입 `.eps`를 fingerprint하고, 종료 코드 0 뒤 임시 MPQ를
다시 열어 CHK raw 파싱과 `VER`/`DIM`/`ERA` 최소 구조를 확인한다. 그 뒤 기준
맵과 진입 소스 fingerprint를 다시 비교하므로 빌드 도중 변경된 입력으로 만든
출력은 승격하지 않는다.

생성 `.eds`에는 `[freeze] freeze: 0`을 고정한다. euddraft의 기본 Freeze
보호는 일반 CHK 경계를 의도적으로 숨겨 위 재검증 계약과 충돌하므로 MVP에서
허용하지 않는다. eudplib가 기본 locale에 작은 placeholder를 두고
locale `0x0409`에 실제 CHK를 저장한 경우 helper가 선택 locale을 명시해
추출하고 Dart가 같은 locale의 목록 메타데이터와 교차 검증한다.

기존 최종 출력은 `replaceExistingOutput`을 명시한 빌드 계획에서만 교체한다.
승인 시점의 fingerprint를 승격 직전에 다시 확인하고, 삭제·변경되었거나
처음 없던 경로에 다른 파일이 생기면 실패한다. 확인된 기존 출력은
`<파일명>.backup-eud-<고유 작업 토큰>.bak`로 이동한 뒤 검증된 임시 출력을
rename한다. 승격 실패 시 자동 복원하며 복원 실패 시 백업은 작업 공간 밖에
보존하고 `EUD_BUILD_PROMOTION_RECOVERY_REQUIRED` 진단으로 안내한다.

`LocalEudBuildFileGateway`는 기준 맵·진입 소스가 일반 파일, 소스 루트와
출력 부모가 일반 디렉터리인지 `followLinks: false`로 확인한다. canonical
진입 소스는 canonical 소스 루트 안에 있어야 하고 canonical 출력 부모는
그 밖에 있어야 한다. `.eds`의 `input`/`output`은 파이프라인만 관리하며
사용자 compiler option으로 재정의할 수 없다. 성공·실패·취소 뒤에는 현재
앱 인스턴스가 소유 토큰으로 등록한 정확한 작업 공간만 정리한다.

## 6. 경로 안전

- 입력, 임시, 출력 경로를 절대 경로로 정규화
- 작업 공간 밖으로 나가는 상대 경로를 명시적으로 검증
- 예약 장치 이름과 잘못된 Windows 경로 처리
- 공백, 한글, 긴 경로 테스트
- 삭제와 정리는 앱이 만든 정확한 임시 디렉터리에만 수행
- broad glob이나 환경 변수만으로 삭제 대상을 정하지 않음

## 7. 자동 저장과 복구

자동 저장본은 원본과 구분되는 앱 데이터 디렉터리에 둔다.

복구 메타데이터:

- 원본 경로와 fingerprint
- 문서 ID
- 저장 시각
- 앱 버전과 포맷 버전
- 자동 저장 데이터 해시
- 마지막 정상 저장 기준점

복구는 항상 새 문서로 열고, 사용자가 확인하기 전 원본에 반영하지 않는다.

## 8. 로그와 개인정보

로그에 포함할 수 있는 정보:

- 앱/도구 버전
- 작업 단계와 오류 코드
- 섹션 이름과 바이트 오프셋
- 프로세스 종료 코드

공유 전 가려야 하는 정보:

- 사용자 홈과 개인 프로젝트 절대 경로
- 환경 변수
- 맵에 포함된 개인 문자열
- 외부 도구가 출력한 토큰이나 계정 정보

진단 보고서 내보내기는 원시 로그와 개인정보 제거본을 구분한다.

현재 EUD 빌드 기록은 최근 20개를 앱 세션 메모리에만 보존한다. build ID,
도구 버전, UTC 시작·종료 시각, 종료 코드와 stdout/stderr 채널은 구조화하지만
원시 줄을 자동으로 디스크에 쓰지 않는다. 영구 manifest나 공유 보고서를
추가할 때에는 저장 경로와 개인정보 제거 여부를 사용자에게 명시한다.

## 9. 외부 구성요소 공급망

- 의존성 버전과 해시를 잠근다.
- 바이너리 다운로드 출처와 버전을 기록한다.
- 자동 업데이트는 서명/해시 검증 설계 전 도입하지 않는다.
- euddraft와 정적으로 링크한 StormLib 등 외부 구성요소의 라이선스와 고지
  파일을 배포물에 포함한다.
- 새 의존성은 실행 코드, 네이티브 코드, 네트워크 권한 여부를 검토한다.

## 10. 사고 대응

데이터 손실 또는 보안 결함이 발견되면:

1. 영향을 받는 저장/빌드 기능을 비활성화하거나 릴리스를 중단한다.
2. 재현 입력과 앱/도구 버전을 보존한다.
3. 원본 변경 여부와 복구 가능성을 먼저 확인한다.
4. 회귀 테스트를 추가한다.
5. 수정 릴리스와 알려진 영향 범위를 기록한다.

실제 사용자 맵은 명시적 동의 없이 이슈나 저장소에 첨부하지 않는다.
