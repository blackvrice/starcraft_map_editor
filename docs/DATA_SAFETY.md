# 데이터 안전과 보안

## 1. 보호 대상

- 사용자의 원본 `.scm`/`.scx`
- epScript와 플러그인 소스
- 자동 저장 및 빌드 결과
- 로컬 설치 경로와 사용자 이름 같은 개인정보
- 앱이 실행할 수 있는 외부 프로세스 권한

## 2. 위협 모델

맵과 EUD 프로젝트는 신뢰할 수 없는 입력일 수 있다.

- 조작된 길이로 메모리/디스크 자원을 과다 사용
- 비정상 MPQ/CHK로 파서 크래시 유도
- 경로 순회를 통한 작업 폴더 밖 파일 접근
- Python 플러그인이나 빌드 스크립트에서 임의 코드 실행
- 심볼릭 링크 또는 경로 충돌로 원본 덮어쓰기
- 로그를 통한 개인 경로와 환경 변수 노출
- 성공처럼 보이는 손상된 부분 출력

이 앱은 맵 보호 해제 도구나 악성 파일 분석 sandbox가 아니다.

## 3. 원본 맵 보호

- 기본 저장은 Save As
- 빌드는 입력과 다른 출력 경로 강제
- 작업 시작과 완료 시 입력 fingerprint 비교
- 최종 파일은 임시 파일을 검증한 뒤 승격
- 출력 경로가 입력과 같은 실제 경로인지 정규화 후 비교
- 기존 출력 파일 교체 전 사용자 확인과 복구 가능한 백업
- 앱 크래시 후 임시 파일을 자동으로 원본에 덮어쓰지 않음

## 4. 바이너리 입력 방어

- 모든 길이와 개수에 상한 적용
- 덧셈/곱셈 overflow를 검사한 뒤 버퍼 접근
- 파일 범위를 벗어나는 섹션 즉시 중단
- 오류 메시지 생성 중에도 원시 페이로드를 무제한 출력하지 않음
- 파싱을 UI isolate와 분리
- fuzz와 손상 픽스처를 회귀 테스트로 유지

상한을 넘는 정상 파일 가능성이 있다면 “손상”으로 단정하지 않고 제한값과 해결 방법을 보여준다.

## 5. 외부 프로세스

- 사용자가 Build/Test를 눌렀을 때만 실행
- 셸 명령 문자열을 만들지 않고 인자 목록 사용
- 현재 사용자와 같은 권한으로 실행
- 실행 파일과 작업 디렉터리를 UI에서 확인 가능
- 환경 변수는 필요한 값만 전달
- timeout과 취소 경로 제공
- 프로세스 트리 종료 정책을 검증
- 종료 코드와 출력 검증이 끝나기 전 성공 표시 금지

Python 플러그인은 파일 접근과 네트워크 접근이 가능한 임의 코드로 간주한다.

## 6. 경로 안전

- 입력, 임시, 출력 경로를 절대 경로로 정규화
- 작업 공간 밖으로 나가는 상대 경로를 명시적으로 검증
- 예약 장치 이름과 잘못된 Windows 경로 처리
- 공백, 한글, 긴 경로 테스트
- 삭제와 정리는 앱이 만든 정확한 임시 디렉터리에만 수행
- broad glob이나 환경 변수만으로 삭제 대상을 정하지 않음

## 7. 자동 저장과 복구

자동 저장본은 원본과 구분되는 앱 데이터 디렉터리에 둔다.

복구 메타데이터:

- 원본 경로와 fingerprint
- 문서 ID
- 저장 시각
- 앱 버전과 포맷 버전
- 자동 저장 데이터 해시
- 마지막 정상 저장 기준점

복구는 항상 새 문서로 열고, 사용자가 확인하기 전 원본에 반영하지 않는다.

## 8. 로그와 개인정보

로그에 포함할 수 있는 정보:

- 앱/도구 버전
- 작업 단계와 오류 코드
- 섹션 이름과 바이트 오프셋
- 프로세스 종료 코드

공유 전 가려야 하는 정보:

- 사용자 홈과 개인 프로젝트 절대 경로
- 환경 변수
- 맵에 포함된 개인 문자열
- 외부 도구가 출력한 토큰이나 계정 정보

진단 보고서 내보내기는 원시 로그와 개인정보 제거본을 구분한다.

## 9. 외부 구성요소 공급망

- 의존성 버전과 해시를 잠근다.
- 바이너리 다운로드 출처와 버전을 기록한다.
- 자동 업데이트는 서명/해시 검증 설계 전 도입하지 않는다.
- euddraft, StormLib 등 외부 구성요소의 라이선스와 고지 파일을 배포물에 포함한다.
- 새 의존성은 실행 코드, 네이티브 코드, 네트워크 권한 여부를 검토한다.

## 10. 사고 대응

데이터 손실 또는 보안 결함이 발견되면:

1. 영향을 받는 저장/빌드 기능을 비활성화하거나 릴리스를 중단한다.
2. 재현 입력과 앱/도구 버전을 보존한다.
3. 원본 변경 여부와 복구 가능성을 먼저 확인한다.
4. 회귀 테스트를 추가한다.
5. 수정 릴리스와 알려진 영향 범위를 기록한다.

실제 사용자 맵은 명시적 동의 없이 이슈나 저장소에 첨부하지 않는다.
