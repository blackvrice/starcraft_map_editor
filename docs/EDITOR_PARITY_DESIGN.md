# 기존 에디터 대비 보완 설계

2026-10-04 설계 제안. **미구현 목표**를 설명하며 현재 클래스/포트가 모두
존재한다는 뜻이 아니다. 근거는 [비교 분석](EDITOR_PARITY_AUDIT_2026-10-04.md),
요구사항 원본은 [제품 요구사항](PRODUCT_REQUIREMENTS.md), 체크박스 원본은
[개발 계획](DEVELOPMENT_PLAN.md)이다.

## 2. 배치와 팔레트

현재 `PlacementCatalogController`, 객체 factory와 문서 공통 기록을 확장한다.
spriteUnit은 THG2 unit-sprite 표현의 flags/ID/소유자/활성 계약을 먼저 검증한다.
pure sprite와 UNIT를 이름만 바꾸어 생성하지 않는다. 미지원 항목은 선택 전에
읽기 전용과 사유를 표시하며 기능 버튼으로 위장하지 않는다.

그림+이름+종류/ID 격자를 유지하고 두다드는 footprint 타일과 overlay를 합성한다.
로컬 게임 자산이 없으면 종류/ID와 누락 상태를 보여주며 다른 그림을 대입하지 않는다.
커서는 footprint·스냅 결과·거절 위치를 표시한다. 클릭 전 읽기 전용 검증과
클릭 시 실제 검증이 같은 순수 domain 정책을 사용한다. 문서 revision이 바뀌면
미리보기를 폐기하고 다시 계산한다.

`PlacementPolicy`(제안)는 격자 표시와 스냅을 분리하고 8/16/32/64/128px 및
검증된 사용자 값을 지원한다. 건물 타일 정렬과 일반 유닛 정렬은 구분한다.
경계/ID/레코드/두다드 지형 검증은 자유 배치에서도 생략하지 않는다.
지형 충돌·전력·크립 검증은 검증 자료가 있을 때만 정상/자유 배치 정책에
반영하며 모르는 경우 '검증 불가'로 표시한다. 게임 건설 가능성을 보증하지 않는다.
기존 맵의 불법/겹친 배치는 읽을 때 자동 삭제하지 않는다.

## 3. 여러 맵과 clipboard

### 문서 수명

`WorkspaceController`(제안)가 안정적인 document ID로 여러 세션을 관리한다.
각 세션은 현재 컨트롤러 묶음, 변경 상태, 시간순 기록, 폼 초안, 카메라,
레이어/선택, 리소스 변경과 EUD/소스 연결을 소유한다. 앱 전역 설정과 검증된
읽기 전용 자산 캐시만 공유한다. 한 세션을 여러 곳에 재사용해 탭을 흉내내지 않는다.
탭 변경은 편집/저장이 아니며 닫기·종료에서는 문서별 dirty와 진행 작업을 확인한다.
비동기 결과는 document ID+revision+요청 ID가 맞을 때만 해당 탭에 적용한다.
저장/빌드/복구 경로 충돌과 동일 파일 중복 열기 정책은 구현 ADR에서 확정한다.

### 복사와 적용

앱 내부 `ClipboardPayload`(제안)는 버전, 원본 타일셋/문서 ID/revision,
상대 좌표, 지원 레코드와 원시 보존 필드, 참조 의존성 집합을 담는다.
기존 같은 문서 raw 복사는 유지하고 새 혼합 경로를 별도 지원표로 활성화한다.
OS clipboard나 타사 브러시 파일을 실행 가능한 입력으로 받지 않는다.

1. 선택된 다수 DD2/THG2 overlay/지형을 하나의 일관된 footprint로 수집한다.
2. 잘린 두다드·알 수 없는 관계·모호한 문자열 표·지원 밖 데이터는 복사/적용을 거부한다.
3. 대상에서 로케이션/문자열/사운드/UNIT class ID·연결/소유자 매핑을 계획한다.
4. ID 충돌·용량·리소스 경로/locale·타일셋 차이와 전체 변경을 읽기 전용으로 보여준다.
5. 명시적 Apply 시 target revision을 재확인하고 한 번의 Undo 명령으로 적용한다.

첫 문서 간 버전은 같은 타일셋의 검증된 객체/리소스만 허용한다. 지형은 raw와
ISOM의 지원 프로필을 분리한다. ISOM은 기존 solver로 대상 경계를 재검증한다.
문자열 바이트/ID를 전역 정규화하거나 서로 다른 맵의 같은 숫자 ID를 같은 의미로
간주하지 않는다. 일반 트리거의 문서 간 복사는 참조 closure가 검증된 후에만
추가하며 raw/EUD/미지원 트리거의 문서 간 이식은 초기 범위에서 제외한다.
한 참조라도 안전하게 옮길 수 없으면 부분 적용하지 않는다. Cut은 먼저 같은
문서 원자 명령으로 구현하고, 문서 간 Move는 두 문서 트랜잭션 설계 전 제공하지 않는다.

## 4. 지형·보조 표시

지형 브러시는 `solveIsomRegion` 등 현재 검증된 엔진을 재사용한다. raw 타일
stamp와 의미 기반 ISOM 브러시를 다른 타입으로 저장하며 서로 자동 치환하지 않는다.
사용자 브러시는 원시 게임 이미지가 아니라 제한된 편집 metadata만 보관한다.
schema·크기·좌표·타일셋/catalog revision을 검증하고 미지원 버전은 읽기 전용이다.
좌우/상하 대칭부터 구현하고 ramp 방향·두다드 대응 자료가 없으면 거부한다.
반사 후 raw ID의 단순 뒤집기로 ISOM 대칭을 구현하지 않는다.

height/buildability/walkability/range/power/creep overlay는 독립적인 읽기 전용
파생 view로 만든다. VF4/CV5/DAT와 문서 revision을 cache key에 넣고
화면 밖 계산을 줄인다. 실제 게임 pathfinder 영역/동적 크립·전력과 같다고
표시하려면 별도 검증이 필요하다. 미확인 영역은 미확인으로 표시한다.

## 5. 설정·문자열·사운드

일반 DAT 기본 수치 조회는 기존 helper 포트 뒤에 추가하고 데이터 빌드/해시와
수치 단위를 기록한다. 이름 조회, CHK override, 기본값 상속과 예상 최종값을
분리하며 기본값 조회 실패 시 0을 표시하지 않는다. 조회만으로 CHK를 변경하지 않는다.

CRGB는 고정 CHK 레이아웃·모드와 COLR 우선순위를 자료/게임으로 확정한 뒤
pure domain editor를 추가한다. 기본/로비 선택/무작위/사용자 RGB 등 검증된
모드만 노출하고 색상 swatch와 수치 입력을 사용한다. 모드 전환은 바이트 차이를
미리보기하며 알 수 없는 모드/중복/손상은 보존·거절한다. 캔버스 색상 캐시를
설정 revision으로 무효화하고 '게임과 동일' 여부는 게임 검증 상태를 따른다.

문자열은 표시 텍스트와 게임 제어 바이트 token을 분리한다. 색상 팔레트는
검증된 token만 삽입하고 알 수 없는 바이트를 가역 표기로 보존한다. 공유 문자열
변경/새 ID 생성의 영향과 참조 수를 보여준다. 기존 UTF-8/raw 계약을 무단 교체하지 않는다.

사운드는 codec 탐지/재생·가져오기 지원표를 분리한다. OGG 등은 런타임과
라이선스·메모리/파일 크기·게임 재생을 검증한 뒤 허용한다. 게임 사운드 선택은
로컬 설치 참조 경로만 사용하고 자산을 저장소/배포물에 포함하지 않는다.

## 6. 트리거와 언어

트리거 검색은 문자열·종류 ID·소유자·활성·조건/액션·참조 ID를 조회하되
검색 자체는 raw 문서를 바꾸지 않는다. 기존 소유자/활성 일괄 변경을 재사용하고
조건/액션·참조 확대는 지원표로 제한한다. 선택 결과의 일괄 변경은 지원된 필드만
영향 미리보기와 한 번의 Undo로 적용한다. 미지원/EUD record는 필터에 남기되
일반 변환/일괄 편집에서 원시 바이트를 유지한다.

일반 스크립트는 [언어 계획 L0~L6](EUD_TOOLCHAIN_LANGUAGE_PLAN.md)의 제한 AST
-> versioned 모델 -> TRIG 경로를 사용한다. 일반 모드는 외부 Python/Lua/EUD
코드를 실행하지 않는다. 전체 Python/epScript/Lua 프로그램의 자동 번역이 아니다.
GUI·스크립트 초안 충돌은 revision으로 막고 Parse/Preview와 Apply를 분리한다.
native EPS/Python은 opaque authored source로 보존하며 EUD Build에서만 실행한다.

소스 작업 공간은 프로젝트 루트 아래 여러 파일, 문법별 색상·정적 완성,
검색·file:line 진단 이동을 제공한다. 루트 밖 import·링크·외부 변경을 검사하고
자동 완성/프로젝트 열기에 interpreter를 실행하지 않는다. 완전한 LSP는 후속이다.

## 7. 실행/출력과 계층

UI -> application use case -> domain validation -> port -> infrastructure
경계를 유지한다. 파일/프로세스/codec/CASC는 UI와 domain에서 직접 호출하지 않는다.
게임 실행은 `GameLaunchGateway`(제안) 뒤에서 설정된 실행 파일과 검증된 출력
맵만 받는다. SC:R 직접 맵 시작 인자가 가능한지 먼저 조사하고 불가능하면
게임에서 파일을 선택하는 수동 흐름과 체크리스트를 제공한다. 셸 결합·주입·
메모리 편집·Battle.net 자동 업로드는 하지 않는다. 게임 성공은 사용자/테스트
관찰이 필요하며 프로세스 생성 성공만으로 판정하지 않는다.

이미지 출력은 별도 렌더 서비스와 출력 gateway에서 영역·레이어·해상도·크기
상한을 검증한다. 로컬 생성물에 대한 자산 라이선스 경계를 확인하고 원본 맵과
같은 경로는 거부한다. 출력을 위해 캔버스의 카메라/선택/dirty를 바꾸지 않는다.

## 8. 품질·최적화와 미결정

256x256/4,096객체 기준 profile 측정을 확장하고 다중 문서 캐시 총량을 제한한다.
초기 목표는 기존 60 FPS/최소30 FPS, UI 동기 작업 100ms 초과 방지다. 시나리오별
하드웨어·버전·레이어·p95 frame time·메모리·cache bytes를 기록하고 수치를
충족하지 못하면 범위를 줄이거나 최적화한 후 다시 확인한다.
키보드 focus/고대비·125/150/200% DPI·1280x720/1920x1080/4K의 이름/그래픽/
미리보기·오류 메시지 clipping을 검사한다. 처음 제작자 최소 3명의 배치·실패
복구·로케이션·트리거·저장 과제를 관찰하며 실패 시 이유와 설계 변경을 남긴다.
참여자 수와 시간 목표는 초기 검증 계획이지 통계적 사용성 보증이 아니다.

구현 전 ADR: 다중 문서 save/duplicate-open 정책, clipboard/브러시 schema와
상한, CRGB modes/precedence, codec 의존성, 게임 실행 인자/수동 fallback.
각 phase의 parser/포맷 조사 결과를 설계에 반영한 뒤 UI를 활성화한다.
미결정을 추측해서 기본값으로 저장하지 않는다.
