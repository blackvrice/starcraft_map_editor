# 에디터 UX

## 1. UX 목표

- 처음 사용하는 사람도 현재 맵, 선택 도구, 저장 상태를 놓치지 않는다.
- 숙련자는 키보드와 다중 선택으로 빠르게 작업한다.
- 위험한 저장과 코드 실행은 명시적으로 구분한다.
- 지원하지 않는 데이터가 조용히 사라지지 않고 상태로 드러난다.
- 오류는 작업을 막은 이유와 다음 행동을 함께 보여준다.

### 상단

- File, Edit, View, Map, Trigger, EUD, Help 메뉴
- 선택 도구, 지형 도구, 객체 도구
- Save As와 Build는 시각적으로 구분
- 현재 빌드 프로필과 실행 상태

### 왼쪽

- 프로젝트 파일과 epScript 소스
- 맵 레이어 표시/잠금
- 객체 팔레트와 검색

### 중앙

- 맵 캔버스와 코드 편집기 탭
- 여러 뷰가 같은 문서 세션을 공유
- 탭에 변경 상태와 오류 상태 표시

### 오른쪽

- 선택 객체의 속성
- 문서/맵 설정
- 지원되지 않는 원시 필드의 읽기 전용 정보

### 하단

- Problems: 구조화된 진단
- Output: 앱 작업 로그
- Build Log: euddraft 원시 출력
- Raw Data: 선택한 CHK 섹션의 검사 뷰

## 4. 맵 열기 흐름

1. 사용자가 파일을 선택한다.
2. 읽기/파싱/검증 단계를 진행 표시한다.
3. 경고가 있어도 안전하게 표시 가능한 경우 읽기 전용 또는 제한 편집으로 연다.
4. 문서 탭에 파일명, 상태, 지원 수준을 표시한다.
5. 심각한 오류는 원본을 변경하지 않았다는 사실과 함께 보고한다.

현재 Open Map은 Windows 기본 파일 선택 대화상자에서 `.scm`/`.scx`를 고르고
읽기, 파싱, 검증 진행 상태를 하단에 표시한다. 성공하면 중앙에 전체 맵을
fit-to-view로 배치한 캔버스를 열고 맵 경계, 화면 밀도에 맞춘 격자와 가시
타일 범위를 표시한다. 정상 SC:R 자산이 준비된 raw는 실제 타일 이미지로,
로딩·누락·실패 raw는 기존 결정적 색상 또는 교차 경고로 표시한다. 휠과 화면 컨트롤로
포인터 중심 확대/축소와 Fit 복귀를 제공하고, `Space`+좌클릭 또는 중간 버튼
드래그로 이동하며, 포인터의 0기준 타일·StarCraft 픽셀 좌표를 표시한다.
이미지 로딩 전과 변환 실패 시에는 원시 값 대체 색상을 유지한다. 전체 `u16`
raw 중 실제 `CV5` 그룹 범위를 벗어났다고 helper가 반환한 값은 데이터 자체를
바꾸지 않고 자홍색 교차 패턴과 unsupported 개수로 구분하며, 타일을 선택하면
raw 값과 그룹·멤버 및 확인된 지원 상태를 함께 표시한다. 도구 모음의 환경 배지를 누르거나
Edit > Settings를 선택하면
StarCraft Data Assets 대화상자가 열린다. 사용자는 Battle.net에서 설치한
StarCraft: Remastered 폴더를 선택하고 CascLib이 로컬 CASC에서 확인한 40개
필수 자산, 제품·빌드·읽은 크기와 누락·손상 자산의 해결 방법을 확인할 수
있다. 앱은 자산 복사나 수동 추출을 요구하지 않는다. 중간 창 너비에서는
배지를 `SC:R • Ready`,
`SC:R • Missing`처럼 축약한다.

좌측에는 Terrain, Locations, Doodads, Sprites, Units 레이어와 각 객체 수,
표시/잠금 토글,
우측 Inspector에는 파일·맵 크기·버전·타일셋·지형·아카이브 요약을 표시하며
하단 Problems에는 구조화된 진단 코드를 노출한다. 정상적인 단일 `MTXM` 격자는
`Editable`, 첫 변경 뒤에는 `Modified`로 표시하고 문서 탭과 상태 표시줄에도
dirty 상태를 표시한다. 편집 불가능한 구조는 `Read-only preview`다.
typed 메타데이터 구조 오류가 있으면 `Restricted`로 표시하고 raw CHK 파싱
실패는 문서를 열지 않는다. `MTXM` 레코드 또는 `DIM ` 기준 타일 수 오류도
Restricted 진단에 포함한다. `MTXM`이 없거나 중복되어도 크기가 유일하면
경계·격자 geometry preview는 가능하지만 임의의 terrain 섹션을 선택하지
않는다. 성공한 파일만 최근 목록에 추가되며 최근 항목을 누르면 파일
대화상자 없이 같은 열기 파이프라인을 다시 실행한다.

경고 요약 예:

```text
맵을 제한 편집 모드로 열었습니다.
- 알 수 없는 CHK 섹션 3개: 그대로 보존됩니다.
- 문자열 인코딩을 확정할 수 없음: 해당 문자열은 읽기 전용입니다.
- 저장 전 추가 검증이 필요합니다.
```

## 5. 저장 흐름

### Save As

- 초기 릴리스의 기본 저장 명령
- 입력과 같은 경로를 선택하면 경고하고 다른 이름을 권장
- 다른 기존 출력은 Windows 교체 확인을 승인한 경우에만 선택 완료
- 예상 변경 섹션과 진단을 저장 전 요약
- 진행 중 임시 파일을 최종 파일처럼 표시하지 않음
- 완료 후 출력 경로, 크기, 검증 상태와 생성된 복구 백업 경로 표시
- 자동 복원 실패 시 수동 복구에 사용할 백업 경로를 차단 진단으로 표시

### 닫기

변경된 문서를 닫을 때 다음 세 행동을 명확히 제공한다.

- Save As
- 변경 버리기
- 취소

빌드 출력과 편집 문서 저장은 다른 동작이다. Build가 현재 맵 편집 내용을 자동 저장하는지 여부를 숨기지 않는다.

## 6. 맵 캔버스 입력

### 기본 도구

- Select
- Pan
- Terrain Brush
- Unit/Object Placement
- Location
- Measure/Inspect

### 입력 원칙

- 마우스 휠: 포인터 중심 확대/축소
- Space+드래그 또는 중간 버튼: 화면 이동
- Escape: 현재 배치/드래그 취소
- Delete: 선택 삭제, 대량 삭제 시 개수 표시
- Ctrl+Z / Ctrl+Y: Undo/Redo
- 격자 스냅 상태를 상태 표시줄에 표시

클릭 우선순위가 모호하면 현재 활성 레이어와 도구를 우선하고, 겹친 객체 선택 메뉴를 제공한다.

현재 레이어 동작은 다음과 같다.

- 표시 순서는 Terrain → Locations → Doodads → Sprites → Units로, 위 레이어가
  아래 레이어 위에 그려진다. 왼쪽 패널은 시각적 스택에 맞춰 역순으로 나열한다.
- 기본 클릭 우선순위는 Units → Sprites → Doodads → Locations → Terrain이다.
  사용자가 활성화한 레이어가 표시되고 잠금 해제 상태이면 가장 먼저 검사한다.
- 눈 아이콘으로 숨긴 레이어는 캔버스와 선택 후보에서 함께 제외된다. 잠근
  레이어는 계속 보이지만 선택과 편집 후보에서는 제외된다.
- `DD2 ` 두다드의 외형은 이미 `MTXM` 지형 타일에 반영되어 있으므로 평상시에는
  별도의 색상 마커를 겹쳐 그리지 않는다. 선택·이동 중인 두다드만 위치 마커로
  강조하며 클릭·박스 선택 후보에는 계속 포함한다.
- 단일 클릭은 현재 우선순위의 첫 객체를 선택 강조하고 왼쪽 패널 아래에 종류,
  레코드 번호, StarCraft 픽셀 좌표를 표시한다. Ctrl/Shift+클릭은 해당 객체를
  현재 다중 선택에 추가하거나 제거한다.
- 빈 곳에서 드래그하면 박스와 교차하는 객체를 선택한다. 객체 레이어가 활성이면
  해당 레이어만, Terrain이 활성이면 표시되고 잠금 해제된 모든 객체 레이어를
  대상으로 한다.
- 선택된 객체에서 드래그를 시작하면 선택 전체의 이동 미리보기를 표시하고
  놓은 위치가 맵 경계 안일 때 StarCraft 픽셀 단위로 이동한다.
- 객체 도구 모음과 Delete 키로 선택을 삭제한다. Ctrl+Z/Ctrl+Y는 현재 활성
  객체 레이어에서 객체 편집 기록을, Terrain 레이어에서 지형 편집 기록을 사용한다.
- 왼쪽 Object Palette는 현재 맵에 이미 있는 유닛·두다드·스프라이트를 type
  ID별로 보여주며 종류, `type`, `#ID` 검색을 지원한다. 항목을 선택하면 해당
  레이어가 활성화되고 캔버스 클릭마다 같은 템플릿을 연속 배치한다. 맵 이름
  카탈로그가 연결되기 전에는 `Unit type 1`처럼 수치 ID를 명시한다.
- 배치 중에는 상단에 현재 템플릿과 `Esc cancel`을 표시하고 커서를 바꾼다.
  박스 선택과 기존 객체 이동은 잠시 비활성화하며 `Escape`, 팔레트 닫기 또는
  레이어 직접 전환으로 문서 변경 없이 배치 모드만 종료한다.
- 활성 객체 레이어를 바꾸면 지형 Brush/Rectangle은 Select로 돌아간다. 겹친
  객체 선택 메뉴는 후속 작업에서 추가한다.

현재 지형 도구는 다음 순서로 사용한다.

1. `Select tile`로 캔버스의 기존 raw `MTXM` 타일을 샘플링한다.
2. 선택 값과 원래 좌표를 도구 모음에서 확인한다.
3. `Brush`로 드래그 경로를 칠하거나 `Rectangle`로 포함 영역을 채운다.
4. Brush 또는 Rectangle 드래그 중 `Escape`를 누르면 해당 드래그 전체를
   적용하지 않고 취소한다.
5. 변경 결과는 `Modified`로 표시되며 원본에는 쓰지 않고 Save As 대상으로만
   전달한다.
6. 도구 모음의 Undo/Redo 또는 `Ctrl+Z`/`Ctrl+Y`로 지형 변경을 되돌리거나
   다시 적용한다.

Brush와 Rectangle은 유효한 타일을 선택하기 전에는 비활성이다. 현재 범위는
`MTXM only · TILE/ISOM preserved`로 항상 표시한다. 이는 게임용 raw 지형
편집이며 외부 에디터 표현을 자동 동기화했다고 오해하게 만들지 않는다.
한 번의 연속 Brush 드래그는 하나의 Undo 단계이며 Rectangle 채우기도 하나의
단계다. Undo 뒤 새 지형 변경을 적용하면 기존 Redo 기록은 제거된다. Undo와
Redo는 맵 작업 화면에서만 활성화하므로 epScript 편집기의 텍스트 기록을
가로채지 않는다. 새 맵을 열거나 Save As 결과를 새 문서로 채택하면 이전 맵의
지형 기록은 초기화된다.

캔버스는 처음 열 때 전체 맵을 맞춰 100%로 표시하고 25%~3200% 범위에서
1.25배 단계로 확대/축소한다. 휠 확대는 포인터 아래 맵 위치를 유지하며 Fit
컨트롤은 100% 중앙 배치로 돌아간다. 이동 시 맵을 완전히 잃어버리지 않도록
확대된 축의 가장자리 일부를 viewport 안에 유지한다. painter는 viewport 밖을
clip하고 가시 타일 범위만 순회하며, 타일 한 칸이 너무 작아지면 격자를 2의
거듭제곱 간격으로 축약한다. 좌표 상태는 타일과 타일당 32픽셀 기준의 맵 픽셀을
모두 0부터 표시하고 맵 밖에서는 대시로 표시한다.

## 6.1 카탈로그 배치 탭

Object Palette 헤더의 `+` 버튼이 `Catalog` 탭을 연다. 카탈로그는 맵 탭 옆의
작업 영역 탭이며, 맵 위를 덮는 창이 아니다. 맵에 이미 있는 레코드만 복제하던
기존 팔레트와 달리 로컬 StarCraft 데이터의 전체 카탈로그에서 새 항목을 고른다.

- 문서 탭 줄에 `<맵 이름>`, `Catalog`, 그리고 epScript 문서가 있으면
  `<소스 이름>` 탭이 함께 놓인다. 탭을 눌러 언제든 오간다.
- 탭 안은 왼쪽 `Tiles`·`Doodads`·`Units`·`Sprites` 목록과 분류 필터, 가운데
  가상화된 썸네일 grid, 오른쪽 큰 미리보기·이름·종류와 숫자 ID·footprint
  크기로 구성된다.
- 검색은 표시 이름, 종류, `#숫자 ID`, 분류 경로를 함께 본다. 타일셋은 열린 맵의
  유일한 `ERA` 값으로 고정되며 탭 상단에 표시한다. 다른 타일셋 항목은 어차피
  배치할 수 없으므로 목록에 넣지 않는다.
- 분류 필터는 현재 페이지가 검증된 분류를 제공할 때만 나온다. 로컬 데이터가
  분류를 주지 않으면 필터를 만들지 않는다.
- 단일 클릭은 상세 미리보기만 바꾸고, 더블 클릭 또는 `Place` 버튼이 선택을
  확정한다. 확정하면 맵 탭으로 돌아가 캔버스에서 배치를 이어간다.
  `Back to map`은 아무것도 확정하지 않고 맵 탭으로 돌아간다. 탭을 열거나
  둘러보는 동작은 문서를 dirty로 만들지 않는다.
- 탭을 다시 열면 이미 불러온 페이지를 그대로 쓰고 helper에 다시 요청하지
  않는다.
- 배치할 수 없는 항목은 숨기지 않고 흐리게 표시하며, 상세 창에 사유 문구와
  진단 코드를 함께 보여준다.
- `Owner` 드롭다운이 새 레코드의 소유 플레이어를 정하고, `Keep placing`을
  켜면 한 번 확정한 선택으로 연속 배치한다. 끄면 한 번 배치한 뒤 선택이 풀린다.
- `Tile`을 확정하면 지형 브러시 값이 되어 기존 Brush/Rectangle 도구로 칠한다.
  `Doodad`와 `Sprite`는 캔버스 클릭을 기다리며, Doodad는 클릭한 타일을
  footprint 중심으로 삼는다.
- 배치를 확정하면 캔버스가 커서 아래에 타일에 스냅된 반투명 footprint ghost를
  그린다. Doodad는 recipe의 폭·높이, Unit과 Sprite는 한 타일이다. 맵 밖으로
  나가는 위치에서는 ghost가 붉게 바뀐다.
- 캔버스 클릭이 거부되면 사유 코드를 그대로 보여주고 문서는 바뀌지 않는다.
  레이어 잠금, 맵 경계, 중복·부재 섹션, 타일셋 불일치, DDData placibility
  불일치가 여기에 해당한다. `Escape`는 확정된 선택을 취소한다.

현재 제한:

- Unit 배치는 helper가 `units.dat` capability를 읽을 수 있을 때만 가능하다.
  읽지 못한 항목은 `SC_CATALOG_ITEM_UNIT_CAPABILITY_UNAVAILABLE`, addon과
  Nydus Canal처럼 관계가 필요한 Unit은
  `SC_CATALOG_ITEM_UNIT_RELATION_REQUIRED` 사유로 비활성 상태를 유지한다.
- sprite-unit은 여전히 배치 대상이 아니다.

## 7. 선택과 Inspector

- 선택된 객체를 캔버스와 레이어 트리에서 동시에 강조
- 단일 유닛·두다드·스프라이트 선택은 오른쪽 Inspector에서 지원 속성을
  편집하고 `Apply properties`로 한 번에 적용한다.
- 숫자가 아니거나 CHK 필드 폭, 맵 경계, 0~100 비율, 두다드 enabled 0/1을
  벗어난 값은 해당 필드 아래에 오류를 표시하고 Apply 전체를 거부한다.
- 다중 선택은 개수와 공통 레이어만 표시한다. 이동·삭제는 계속 가능하지만
  속성 편집은 한 객체를 선택할 때만 제공한다.
- 원시 flags와 예약 필드는 `Preserved raw fields` 아래 읽기 전용 16진 값으로
  표시한다. 잠긴 레이어와 제한 편집 세션은 필드를 비활성화한다.
- Locations 레이어의 `New location`을 누르면 단일 생성 모드가 시작된다. 캔버스의
  빈 영역을 드래그해 경계를 정하며, 생성 후 새 로케이션을 선택하고 자동으로
  일반 선택 모드로 돌아간다. `Escape`, 버튼 재선택 또는 레이어 전환은 적용 전
  생성 모드만 취소한다.
- 단일 로케이션 Inspector는 ID, left/top/right/bottom, 이름, string ID와
  elevation flags를 표시한다. 경계는 맵 픽셀 범위 안에서 left < right,
  top < bottom이어야 하며 이름은 UTF-8 255바이트 이하로 제한한다. Apply가
  실패하면 필드별 오류를 표시하고 문서를 바꾸지 않는다.
- 이름 변경은 기존 문자열을 공유하는 다른 참조를 바꾸지 않는 새 문자열 ID
  방식임을 안내한다. 안전하게 선택할 수 있는 문자열 표가 없으면 이름 입력과
  그 사유만 비활성화하고 경계 편집은 계속 허용한다.
- 맵을 열거나 저장한 뒤, 그리고 객체 편집·Undo/Redo 뒤 좌표·플레이어·문자열
  의미 경고를 Problems에 표시한다. 항목에는 진단 코드, CHK section과 byte
  offset이 포함된다. 비표준 EUD 값을 자동 변경하거나 의미 경고만으로 편집을
  잠그지 않으며, 사용자가 값을 고치면 해당 경고가 즉시 사라진다.

### 7.1 계획된 기본 설정과 제작 도구

현재 File → Player Settings에서 플레이어 1~8의 슬롯·종족·기본 색상을 편집한다.
플레이어를 전환해도 입력은 유지되며 Apply는 모아 둔 변경을 한 명령으로 적용한다.
누락·중복·손상된 그룹은 사유와 함께 비활성화하고 플레이어 9~12는 읽기 전용이다.
시작 위치의 누락·중복·소유자 경고를 표시하며 자동 수정하지 않는다. 상세 보존
규칙과 CRGB·캔버스 색상 미리보기 제한은 [플레이어 설정](PLAYER_SETTINGS.md)을 따른다.

현재 `File → Map Information…`에서 맵 제목과 설명을 편집할 수 있다.
입력만으로 문서는 바뀌지 않으며 Cancel은 미적용 입력을 폐기한다. Apply는
제목·설명을 한 명령으로 적용하고 창 안의 Undo/Redo는 객체·로케이션과 공유하는
편집 기록의 실제 명령 이름을 표시한다. 적용한 내용은 Save As로 저장한다.
다른 객체가 사용하는 기존 문자열 ID는 유지하고 변경한 필드만 새 ID로 연결한다.
단일 정상 SPRP와 안전한 STR 또는 STRx 하나가 있어야 하며, 중복·손상·잘못된
참조나 기존 텍스트의 UTF-8 해석 실패 시 이유를 표시하고 편집을 차단한다.
창을 연 뒤 문서가 달라졌으면 다시 열도록 안내하며 오래된 입력을 적용하지 않는다.

File → Force Settings에서 플레이어별 세력 배정과 세력별 이름·동맹·공동 승리·
시야 공유·시작 위치 무작위화를 입력한다. 세력을 바꿔도 입력을 유지하고 Apply는
모든 변경을 한 명령으로 적용한다. Cancel, 공유 Undo/Redo와 Save As를 지원한다.
이름이 안전하게 해석되지 않아도 배정·옵션은 독립적으로 편집할 수 있다.
[세력 설정 지원 범위](FORCE_SETTINGS.md)에 오류 처리와 문자열 보존 규칙을 기록한다.

File → Unit Settings에서 유닛 종류별 이름·체력·실드·방어력·생산 비용/시간과
무기 ID별 기본·추가 피해량을 편집한다. 선택을 바꿔도 입력을 유지하며 Apply,
Cancel, 공유 Undo/Redo를 지원한다. 기본값 복원은 선택 유닛의 플래그만 바꾸고
저장된 사용자 값을 보존한다. 로컬 DAT의 직접 무기 참조·서브유닛 경로 목록과
출처를 표시하고, 읽기 실패는 빈 목록과 구분한다.
[유닛 설정 지원 범위](UNIT_SETTINGS.md)에 단위·한계·바이트 보존 규칙을 기록한다.

아래는 [기본 기능 대조](BASIC_EDITOR_COVERAGE.md)로 보완한 미구현 흐름이다.
현재 UI가 제공한다는 뜻이 아니며 M6.3~M7에서 순서대로 구현한다.

- Map Settings는 맵 정보, Players/Forces, Units, Upgrades, Technologies를
  구분한다. Units의 종류 전체 설정과 캔버스 Inspector의 개별 객체 속성을
  이름과 설명으로 구분하고, 기본값 사용·사용자 값·플레이어별 상속을 표시한다.
- 설정 목록을 탐색하거나 값을 입력하는 동안에는 문서를 바꾸지 않는다.
  Apply는 검증된 변경을 하나의 명령으로 적용하고 Cancel은 입력을 폐기한다.
  공유 문자열/무기나 선택한 플레이어 전체에 영향이 있으면 적용 범위를 보여준다.
- New Map은 크기·타일셋·초기 지형과 기본 설정을 고른 뒤 메모리 문서를 만든다.
  첫 저장은 Save As다. 기존 맵 크기 변경은 잘릴 영역과 객체 영향을 먼저 보여준다.
- 기본 등각 지형 도구와 raw 타일 도구를 구분하고, Fog of War는 편집 중인
  플레이어를 항상 표시한다. 미니맵 이동, 영역 복사/붙여넣기와 공통 Undo를 제공한다.
- 문자열·사운드 관리 화면은 사용처를 표시한다. 사용처를 완전히 알 수 없으면
  미사용으로 단정해 삭제하지 않는다. 브리핑은 일반 트리거와 별도 화면에서
  플레이어별 텍스트·초상화·소리·시간 순서를 편집한다.

## 8. EUD 작업 흐름

### 8.1 목표 작업 흐름

아래는 최종 사용자 흐름이다. 현재 제공 범위는 8.2절과 구분한다.

1. 기준 맵과 소스 폴더를 연다.
2. 도구 상태 영역에서 euddraft 버전을 확인한다.
3. epScript를 편집한다.
4. Build를 실행한다.
5. Problems에서 오류를 선택해 코드 위치로 이동한다.
6. 성공 결과의 경로와 출력 해시를 확인한다.
7. 명시적인 Test in StarCraft 동작으로 실행한다.

빌드 버튼은 도구 실행을 의미하므로 첫 실행 시 대상과 출력 경로를 보여준다.

### 8.2 현재 구현과 남은 연결

현재 첫 편집기 수직 조각은 EUD 메뉴나 도구 모음의 `New epScript`로 단일
`main.eps` 메모리 문서를 연다. 중앙의 맵/코드 문서 탭, 줄 번호, 커서 위치,
epScript 모드와 Clean/Modified 상태를 표시하며 맵 탭으로 이동해도 입력
텍스트를 보존한다. 저장되지 않은 텍스트의 교체·닫기는 Application 계층에서
명시적 discard 없이는 거부한다. 실제 `.eps` 열기·저장, 외부 변경 감지,
구문 강조와 찾기/바꾸기는 후속 단계다.

준비된 EUD 요청이 있으면 도구 모음과 EUD 메뉴의 Build가 활성화된다.
실행 중에는 같은 위치가 Cancel로 바뀌어 중복 빌드를 막고, Build Log 탭이
자동으로 선택되어 euddraft 원시 출력을 보여준다. Problems는 맵 진단과
빌드 진단을 함께 표시하고 Output은 일반 작업 진행을 표시한다. 빌드 설정 UI에서
준비된 요청을 연결하기 전에는 Build가 비활성 상태이며 Build Log에
`Build settings are not ready`를 표시한다. 비어 있는 경로를 추측해 외부
도구를 실행하지 않는다.

Build Log 상단은 build ID, euddraft 버전, 성공·실패·취소 결과와 종료 코드,
UTC 시작·종료 시각을 먼저 보여준다. 아래에는 순서가 유지된 각 줄을
`[stdout]` 또는 `[stderr]`로 구분하고 구조화 진단 코드를 함께 표시한다.
구조화 진단에 위치가 있으면 Build Log 메시지 앞과 Problems 행 오른쪽에
`file:line[:column]`을 표시한다. 현재 공식 epScript 오류는 파일과 행만
제공하므로 열을 추정해 보여주지 않는다.
최근 20개 기록은 현재 앱 세션에서 유지되지만 원시 로그를 사용자 동의 없이
파일로 저장하지 않는다.

### 8.3 계획된 EUD 확장 탭

아래는 M6.3.1·M6.3.2·M7.1의 미구현 화면 설계다.

M6.3.1에서 Unit Settings에 `기본 설정`과 `EUD 확장`을 나눈다. EUD 확장은
유닛·지상 무기·공중 무기를 구분하고 사거리, 실드 활성 여부, 피해 유형과 지원
필드를 제공한다. 최대 실드 수치의 일반 설정과 실드 기능 추가는 별도로 표시한다.
항목마다 원본/최종값, 기본값 또는 override, 단위, 버전 지원 여부와 공유 데이터의
영향 유닛 목록을 보여준다. 피해 유형과 공격 대상/효과를 같은 선택란에 섞지 않는다.

Apply는 선언적 프로젝트 설정만 바꾸며 Undo할 수 있다. `프로젝트 저장`, 일반 맵의
`Save As`, 효과를 반영하는 `EUD Build`와 마지막 빌드가 최신인지 구분한다.
빌드 전 생성 코드와 변경 요약을 볼 수 있고 미지원 필드는 이유와 함께 비활성화한다.
첫 버전은 종류별 전역 초기 설정이며 개별 객체/플레이어별 실시간 설정으로 표시하지
않는다. 상세 필드와 지원 기준은 [EUD 확장 설정 설계](EUD_EXTENSIONS.md)를 따른다.

M6.3.2는 Upgrades, Technologies, Players, Graphics에도 공통 `EUD 확장` 탭을
연결한다. Graphics는 Sprite/Image와 기존 Movement 설정을 구분한다. 같은 공유
항목은 어느 화면에서 열어도 같은 값이며, 대상 영역·적용 시점·지원 상태와 영향
목록을 표시한다. 모든 기본 항목을 EUD로 다시 만드는 탭은 아니다.
Graphics/Sounds의 유닛 초상화·응답 음성 선택은 검증된 게임 자산 참조로 제공하며
맵에 가져온 소리 파일 재생과 구분한다.

M7.1에서 Triggers, Object Inspector, Locations, Text/Sound 및 설정 화면의
`실행 규칙` 연결을 제공한다. 조건·대상·필드·값·1회/주기를 폼으로 편집하고
일반 트리거 액션과 EUD 전용 항목을 구분한다. 런타임 객체를 아직 식별할 수 없는
개별 속성은 비활성화하며 현재 CHK 레코드를 살아 있는 CUnit으로 표시하지 않는다.
클라이언트 텍스트/소리 표시와 공통 게임 상태 변경은 서로 다른 실행 영역이다.
미지원 category는 검증 대기 이유를 보여주며 Apply/Build할 수 있는 것처럼 표시하지 않는다.

## 9. 상태와 피드백

오래 걸리는 작업은 다음 상태를 가진다.

- queued
- reading
- parsing
- validating
- writing
- compiling
- verifying
- succeeded
- failed
- cancelled

단순 spinner만 표시하지 않고 현재 단계를 텍스트로 보여준다. 취소할 수 없는 최종 파일 교체 단계에서는 그 사실을 표시한다.

## 10. 접근성

- 모든 핵심 명령에 키보드 접근 제공
- 색상만으로 오류, 선택, 플레이어를 구분하지 않음
- 텍스트 배율에서 패널이 겹치지 않도록 함
- 고대비 테마에서도 선택 테두리와 격자가 보이도록 함
- 아이콘에는 tooltip과 semantic label 제공
- 단축키는 Help에서 검색 가능하게 제공

- StarCraft: Remastered 설치 경로와 40개 필수 CASC 자산 검사
- euddraft 경로와 프로필
- 자동 저장 간격과 보관 수
- 캔버스 격자/레이어 기본값
- 로그 개인정보 가리기

프로젝트 설정과 사용자별 로컬 경로를 분리한다.

StarCraft 데이터 자산 대화상자는 선택 설치 경로, 현재 검사 상태와
found/required 개수를 항상 보여준다. 준비되면 CASC 제품·빌드, 읽은 MiB,
CascLib revision과 helper 버전도 표시한다. Choose Installation, Refresh,
Clear는 장기 작업 중 중복 실행되지 않으며 취소는 기존 설정을 유지한다.
설치가 없거나 불완전하면 Battle.net의 Scan and Repair를 해결 방법으로
안내하고 환경 배지와 Problems에 경고를 남기되 현재 대체 캔버스와 Save As를
막지 않는다.

## 유닛 생산 허용 (M6.3)

File → Unit Availability…에서 맵 기본값과 플레이어별 허용/상속을 편집한다.
단일 5700바이트 PUNI의 변경 필드만 교체하며 상속 전환 시 개별 값을 보존한다.

## 업그레이드 설정 (M6.3)

File → Upgrade Settings…에서 비용·시간·증가량과 플레이어별 시작/최대 레벨을 편집한다.
버전별 UPGS/UPGx와 UPGR/PUPx를 선택하고 비용/레벨 그룹을 독립 검증한다.
UPGx 오프셋 61의 예약 바이트를 보존한다. [지원·검증 규칙](UPGRADE_SETTINGS.md)을 따른다.

## 테크 설정 (M6.3)

File → Tech Settings…에서 비용·연구 시간·에너지와 플레이어별 허용·연구 완료를 편집한다.
TECS/TECx와 PTEC/PTEx를 버전별로 선택하며 기본값 상속은 저장 값을 보존한다.
[지원 범위와 검증](TECH_SETTINGS.md)을 따른다.
