# 에디터 UX

## 1. UX 목표

- 처음 사용하는 사람도 현재 맵, 선택 도구, 저장 상태를 놓치지 않는다.
- 숙련자는 키보드와 다중 선택으로 빠르게 작업한다.
- 위험한 저장과 코드 실행은 명시적으로 구분한다.
- 지원하지 않는 데이터가 조용히 사라지지 않고 상태로 드러난다.
- 오류는 작업을 막은 이유와 다음 행동을 함께 보여준다.

### 상단

- File, Edit, View, Map, Trigger, EUD, Help 메뉴
- 선택 도구, 지형 도구, 객체 도구
- Save As와 Build는 시각적으로 구분
- 현재 빌드 프로필과 실행 상태

### 왼쪽

- 프로젝트 파일과 epScript 소스
- 맵 레이어 표시/잠금
- 객체 팔레트와 검색

### 중앙

- 맵 캔버스와 코드 편집기 탭
- 여러 뷰가 같은 문서 세션을 공유
- 탭에 변경 상태와 오류 상태 표시

### 오른쪽

- 선택 객체의 속성
- 문서/맵 설정
- 지원되지 않는 원시 필드의 읽기 전용 정보

### 하단

- Problems: 구조화된 진단
- Output: 앱 작업 로그
- Build Log: euddraft 원시 출력
- Raw Data: 선택한 CHK 섹션의 검사 뷰

## 3. 시작 화면

초기 항목:

- Open Map
- Open EUD Project
- New Map은 포맷 기반이 안정화된 뒤 활성화
- 최근 파일
- euddraft와 StarCraft 설정 상태
- 문서와 예제 링크

현재 지원하지 않는 기능은 동작하지 않는 버튼으로 남기기보다 숨기거나 “계획됨”으로 명확히 표시한다.

## 4. 맵 열기 흐름

1. 사용자가 파일을 선택한다.
2. 읽기/파싱/검증 단계를 진행 표시한다.
3. 경고가 있어도 안전하게 표시 가능한 경우 읽기 전용 또는 제한 편집으로 연다.
4. 문서 탭에 파일명, 상태, 지원 수준을 표시한다.
5. 심각한 오류는 원본을 변경하지 않았다는 사실과 함께 보고한다.

현재 Open Map은 Windows 기본 파일 선택 대화상자에서 `.scm`/`.scx`를 고르고
읽기, 파싱, 검증 진행 상태를 하단에 표시한다. 성공하면 중앙에 전체 맵을
fit-to-view로 배치한 캔버스를 열고 맵 경계, 화면 밀도에 맞춘 격자,
가시 타일 범위와 원시 `MTXM` 대체 색상을 표시한다. 휠과 화면 컨트롤로
포인터 중심 확대/축소와 Fit 복귀를 제공하고, `Space`+좌클릭 또는 중간 버튼
드래그로 이동하며, 포인터의 0기준 타일·StarCraft 픽셀 좌표를 표시한다.
실제 StarCraft 타일 이미지는 아직 로딩하지 않으며 원시 값 대체 색상을
유지한다. 도구 모음의 환경 배지를 누르거나 Edit > Settings를 선택하면
StarCraft Data Assets 대화상자가 열린다. 사용자는 Battle.net에서 설치한
StarCraft: Remastered 폴더를 선택하고 CascLib이 로컬 CASC에서 확인한 40개
필수 자산, 제품·빌드·읽은 크기와 누락·손상 자산의 해결 방법을 확인할 수
있다. 앱은 자산 복사나 수동 추출을 요구하지 않는다. 중간 창 너비에서는
배지를 `SC:R • Ready`,
`SC:R • Missing`처럼 축약한다.

좌측에는 아카이브 항목,
우측 Inspector에는 파일·맵 크기·버전·타일셋·지형·아카이브 요약을 표시하며
하단 Problems에는 구조화된 진단 코드를 노출한다. 정상적인 단일 `MTXM` 격자는
`Editable`, 첫 변경 뒤에는 `Modified`로 표시하고 문서 탭과 상태 표시줄에도
dirty 상태를 표시한다. 편집 불가능한 구조는 `Read-only preview`다.
typed 메타데이터 구조 오류가 있으면 `Restricted`로 표시하고 raw CHK 파싱
실패는 문서를 열지 않는다. `MTXM` 레코드 또는 `DIM ` 기준 타일 수 오류도
Restricted 진단에 포함한다. `MTXM`이 없거나 중복되어도 크기가 유일하면
경계·격자 geometry preview는 가능하지만 임의의 terrain 섹션을 선택하지
않는다. 성공한 파일만 최근 목록에 추가되며 최근 항목을 누르면 파일
대화상자 없이 같은 열기 파이프라인을 다시 실행한다.

경고 요약 예:

```text
맵을 제한 편집 모드로 열었습니다.
- 알 수 없는 CHK 섹션 3개: 그대로 보존됩니다.
- 문자열 인코딩을 확정할 수 없음: 해당 문자열은 읽기 전용입니다.
- 저장 전 추가 검증이 필요합니다.
```

## 5. 저장 흐름

### Save As

- 초기 릴리스의 기본 저장 명령
- 입력과 같은 경로를 선택하면 경고하고 다른 이름을 권장
- 다른 기존 출력은 Windows 교체 확인을 승인한 경우에만 선택 완료
- 예상 변경 섹션과 진단을 저장 전 요약
- 진행 중 임시 파일을 최종 파일처럼 표시하지 않음
- 완료 후 출력 경로, 크기, 검증 상태와 생성된 복구 백업 경로 표시
- 자동 복원 실패 시 수동 복구에 사용할 백업 경로를 차단 진단으로 표시

### 닫기

변경된 문서를 닫을 때 다음 세 행동을 명확히 제공한다.

- Save As
- 변경 버리기
- 취소

빌드 출력과 편집 문서 저장은 다른 동작이다. Build가 현재 맵 편집 내용을 자동 저장하는지 여부를 숨기지 않는다.

## 6. 맵 캔버스 입력

### 기본 도구

- Select
- Pan
- Terrain Brush
- Unit/Object Placement
- Location
- Measure/Inspect

### 입력 원칙

- 마우스 휠: 포인터 중심 확대/축소
- Space+드래그 또는 중간 버튼: 화면 이동
- Escape: 현재 배치/드래그 취소
- Delete: 선택 삭제, 대량 삭제 시 개수 표시
- Ctrl+Z / Ctrl+Y: Undo/Redo
- 격자 스냅 상태를 상태 표시줄에 표시

클릭 우선순위가 모호하면 현재 활성 레이어와 도구를 우선하고, 겹친 객체 선택 메뉴를 제공한다.

현재 지형 도구는 다음 순서로 사용한다.

1. `Select tile`로 캔버스의 기존 raw `MTXM` 타일을 샘플링한다.
2. 선택 값과 원래 좌표를 도구 모음에서 확인한다.
3. `Brush`로 드래그 경로를 칠하거나 `Rectangle`로 포함 영역을 채운다.
4. Brush 또는 Rectangle 드래그 중 `Escape`를 누르면 해당 드래그 전체를
   적용하지 않고 취소한다.
5. 변경 결과는 `Modified`로 표시되며 원본에는 쓰지 않고 Save As 대상으로만
   전달한다.
6. 도구 모음의 Undo/Redo 또는 `Ctrl+Z`/`Ctrl+Y`로 지형 변경을 되돌리거나
   다시 적용한다.

Brush와 Rectangle은 유효한 타일을 선택하기 전에는 비활성이다. 현재 범위는
`MTXM only · TILE/ISOM preserved`로 항상 표시한다. 이는 게임용 raw 지형
편집이며 외부 에디터 표현을 자동 동기화했다고 오해하게 만들지 않는다.
한 번의 연속 Brush 드래그는 하나의 Undo 단계이며 Rectangle 채우기도 하나의
단계다. Undo 뒤 새 지형 변경을 적용하면 기존 Redo 기록은 제거된다. Undo와
Redo는 맵 작업 화면에서만 활성화하므로 epScript 편집기의 텍스트 기록을
가로채지 않는다. 새 맵을 열거나 Save As 결과를 새 문서로 채택하면 이전 맵의
지형 기록은 초기화된다.

캔버스는 처음 열 때 전체 맵을 맞춰 100%로 표시하고 25%~3200% 범위에서
1.25배 단계로 확대/축소한다. 휠 확대는 포인터 아래 맵 위치를 유지하며 Fit
컨트롤은 100% 중앙 배치로 돌아간다. 이동 시 맵을 완전히 잃어버리지 않도록
확대된 축의 가장자리 일부를 viewport 안에 유지한다. painter는 viewport 밖을
clip하고 가시 타일 범위만 순회하며, 타일 한 칸이 너무 작아지면 격자를 2의
거듭제곱 간격으로 축약한다. 좌표 상태는 타일과 타일당 32픽셀 기준의 맵 픽셀을
모두 0부터 표시하고 맵 밖에서는 대시로 표시한다.

## 7. 선택과 Inspector

- 선택된 객체를 캔버스와 레이어 트리에서 동시에 강조
- 다중 선택은 공통 속성만 표시
- 혼합 값은 빈 값과 다른 상태로 표시
- 입력 중 검증 오류는 필드 옆에 표시
- 즉시 적용과 Apply 버튼 방식 중 하나를 패널별로 일관되게 사용
- 원시/예약 필드는 읽기 전용으로 표시하고 툴팁으로 보존 정책 설명

## 8. EUD 작업 흐름

1. 기준 맵과 소스 폴더를 연다.
2. 도구 상태 영역에서 euddraft 버전을 확인한다.
3. epScript를 편집한다.
4. Build를 실행한다.
5. Problems에서 오류를 선택해 코드 위치로 이동한다.
6. 성공 결과의 경로와 출력 해시를 확인한다.
7. 명시적인 Test in StarCraft 동작으로 실행한다.

빌드 버튼은 도구 실행을 의미하므로 첫 실행 시 대상과 출력 경로를 보여준다.

현재 첫 편집기 수직 조각은 EUD 메뉴나 도구 모음의 `New epScript`로 단일
`main.eps` 메모리 문서를 연다. 중앙의 맵/코드 문서 탭, 줄 번호, 커서 위치,
epScript 모드와 Clean/Modified 상태를 표시하며 맵 탭으로 이동해도 입력
텍스트를 보존한다. 저장되지 않은 텍스트의 교체·닫기는 Application 계층에서
명시적 discard 없이는 거부한다. 실제 `.eps` 열기·저장, 외부 변경 감지,
구문 강조와 찾기/바꾸기는 후속 단계다.

준비된 EUD 요청이 있으면 도구 모음과 EUD 메뉴의 Build가 활성화된다.
실행 중에는 같은 위치가 Cancel로 바뀌어 중복 빌드를 막고, Build Log 탭이
자동으로 선택되어 euddraft 원시 출력을 보여준다. Problems는 맵 진단과
빌드 진단을 함께 표시하고 Output은 일반 작업 진행을 표시한다. 아직 빌드
설정과 `.eds` 생성 흐름이 없을 때 Build는 비활성 상태이며 Build Log에
`Build settings are not ready`를 표시한다. 비어 있는 경로를 추측해 외부
도구를 실행하지 않는다.

Build Log 상단은 build ID, euddraft 버전, 성공·실패·취소 결과와 종료 코드,
UTC 시작·종료 시각을 먼저 보여준다. 아래에는 순서가 유지된 각 줄을
`[stdout]` 또는 `[stderr]`로 구분하고 구조화 진단 코드를 함께 표시한다.
구조화 진단에 위치가 있으면 Build Log 메시지 앞과 Problems 행 오른쪽에
`file:line[:column]`을 표시한다. 현재 공식 epScript 오류는 파일과 행만
제공하므로 열을 추정해 보여주지 않는다.
최근 20개 기록은 현재 앱 세션에서 유지되지만 원시 로그를 사용자 동의 없이
파일로 저장하지 않는다.

## 9. 상태와 피드백

오래 걸리는 작업은 다음 상태를 가진다.

- queued
- reading
- parsing
- validating
- writing
- compiling
- verifying
- succeeded
- failed
- cancelled

단순 spinner만 표시하지 않고 현재 단계를 텍스트로 보여준다. 취소할 수 없는 최종 파일 교체 단계에서는 그 사실을 표시한다.

## 10. 접근성

- 모든 핵심 명령에 키보드 접근 제공
- 색상만으로 오류, 선택, 플레이어를 구분하지 않음
- 텍스트 배율에서 패널이 겹치지 않도록 함
- 고대비 테마에서도 선택 테두리와 격자가 보이도록 함
- 아이콘에는 tooltip과 semantic label 제공
- 단축키는 Help에서 검색 가능하게 제공

## 11. 사용자 설정

- 테마와 UI 배율
- 기본 작업 폴더
- StarCraft: Remastered 설치 경로와 40개 필수 CASC 자산 검사
- euddraft 경로와 프로필
- 자동 저장 간격과 보관 수
- 캔버스 격자/레이어 기본값
- 로그 개인정보 가리기

프로젝트 설정과 사용자별 로컬 경로를 분리한다.

StarCraft 데이터 자산 대화상자는 선택 설치 경로, 현재 검사 상태와
found/required 개수를 항상 보여준다. 준비되면 CASC 제품·빌드, 읽은 MiB,
CascLib revision과 helper 버전도 표시한다. Choose Installation, Refresh,
Clear는 장기 작업 중 중복 실행되지 않으며 취소는 기존 설정을 유지한다.
설치가 없거나 불완전하면 Battle.net의 Scan and Repair를 해결 방법으로
안내하고 환경 배지와 Problems에 경고를 남기되 현재 대체 캔버스와 Save As를
막지 않는다.

## 12. UX 완료 조건

새 기능은 다음 질문에 답할 수 있어야 한다.

- 사용자가 어디에서 시작하는가?
- 진행 중이라는 것을 어떻게 아는가?
- 성공 결과가 무엇인가?
- 실패 이유와 다음 행동은 무엇인가?
- 원본 파일이 변경되는가?
- 되돌리거나 복구할 수 있는가?
- 키보드만으로 핵심 흐름을 수행할 수 있는가?
