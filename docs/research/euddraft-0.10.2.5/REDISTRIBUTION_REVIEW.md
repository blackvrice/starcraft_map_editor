# 동봉 조건 검토 및 필수 모듈 검사 보완

2026-09-16 X1 진행 기록. 전체 동봉 승인 상태는 여전히 `pending`이다.
이 문서는 확인된 코드 동작과 남은 배포 근거를 구분한다.

## freezeMpq는 삭제 가능한 선택 파일이 아님

고정 커밋의 [applyeuddraft.py](https://github.com/armoha/euddraft/blob/761d63fca7a1663eeb7ec00c581269a2a65af5c2/applyeuddraft.py#L30)는
모듈 최상위에서 freezeMpq를 import한다. 보호 기능 호출 자체는 나중에 설정으로
분기하지만, `freeze: 0`으로 import를 생략하지 않는다. 배포본과 태그의 파일 해시가
다르다는 이유로 freezeMpq를 삭제하거나 태그 파일로 교체하는 것은 채택하지 않는다.

이 조사에서 앱의 설치 검사가 해당 필수 파일을 검사하지 않는 누락을 발견해 수정했다.
`LocalEudToolInspector`는 `lib/freezeMpq.pyd`가 없는 경우, 0바이트인 경우,
같은 경로가 디렉터리인 경우 `EUD_TOOL_COMPANION_MISSING`을 반환한다.
실패 결과에 경로와 공식 배포본 재추출 안내를 남기며 빌드 준비 전에 차단한다.
불완전한 목록을 넣은 동봉 manifest도 필수 파일 검사를 우회하지 않는다.
존재·크기 검사만으로 외부 모듈의 ABI나 정상 실행을 보장하지는 않는다.

## 고지 검토의 현재 결론

| 항목 | 확인한 근거 | 남은 조건 |
| --- | --- | --- |
| euddraft·epTrace/BlackBone | ZIP `license.txt`에 MIT 및 저작권 고지 존재 | 최종 배포 고지 묶음에 원문 보존 및 포함 범위 대조 |
| Python·eudplib | 공식 ZIP/wheel 일치 및 고지 위치 확인 | 표준 라이브러리와 Rust 등 전이 의존성까지 고지 검토 |
| VC 런타임 | ZIP에 Microsoft Visual C++ 2015–2022 Runtime 사용권 문서 존재 | 배포에 사용할 정식 획득 경로·해당 Visual Studio 사용권 및 배포 조건 확인 |
| freezeMpq | 배포/태그 해시 차이, 무조건 import 확인 | 배포본의 빌드·소스/고지 범위 근거 확보 |
| 플러그인·기타 라이브러리 | 전체 파일 및 고지 위치 목록 확보 | 최종 포함할 파일별 고지·전이 의존성 검토 |

VC 런타임의 포함된 사용권 문서만으로 앱 재배포 근거가 확보됐다고 표시하지 않는다.
[Microsoft의 Visual Studio 2022 배포 안내](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution#visual-c-runtime-files)는
정식 라이선스를 보유한 Visual Studio 사용자의 배포를 해당 제품 조건과 연결하고,
허용된 redist 파일을 수정하지 않을 것을 명시한다. 이 저장소 조사로 사용자의
라이선스 보유 상태를 추정하지 않는다. 실제 배포 패키지를 만들 때 획득 경로와 적용 조건을 기록한다.

추가 조사 결과가 나오기 전에도 외부 설치 선택·검사 기능의 개발은 진행할 수 있다.
앱에 미검토 바이너리를 동봉하거나 production manifest를 활성화하는 단계는 남아 있다.
다음 구현 단위는 도구 선택/진단 흐름을 준비하고, 실제 동봉 활성화는 별도 인수로 유지한다.

## 검증 방법

기본 회귀 테스트는 프로젝트/사용자/동봉 경로 × 누락/빈 파일/디렉터리 9개 조합을 검사한다.
공식 ZIP은 기존 공개 해시를 재확인한 뒤 무시되는 `build/` 아래에 새로 추출했다.
`EUDDRAFT_TEST_INSTALLATION`을 해당 폴더로 설정해 외부 검사 및 조사 manifest의
전체 파일 대조를 수행한다. 선택 스모크는 수정되지 않은 0.10.2.5 공식 배포본을 요구한다.
두 검사는 파일만 읽으며 euddraft를 실행하지 않는다. 설치·컴파일·게임 호환성은 별도 인수다.

검증 결과: 정적 분석 및 전체 테스트 613개 통과·10개 skip. 공식 설치 검사 2개와
추가한 손상 회귀 9개가 포함됐다. 변경 파일 포맷은 통과했으며 전체 비쓰기 포맷은
기존 infrastructure 테스트 4개의 형식 차이로 실패했다(해당 파일 미수정).
SDK는 Flutter 3.47.2 / Dart 3.13.2로 기준 3.44.8 / 3.12와 다르다.
UI·네이티브 helper 변경이 없어 Windows 빌드는 반복하지 않았다. 실제 컴파일·게임
스모크는 실행하지 않았으므로 이번 설치 검사 결과로 실행 호환성을 보장하지 않는다.
