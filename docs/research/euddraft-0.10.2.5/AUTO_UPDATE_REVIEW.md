# 자동 업데이트와 빌드 도구 재검사 (2026-09-16)

## 관찰과 이전 기록 정정

Prepare EUD Build 구현 때 사용한 별도 실행 복사본을 후속 조사한 결과,
`VERSION`이 0.11.0.1로 바뀌었고 `_update.bat`, `python314.dll` 등 새 파일이 있었다.
원본 ZIP과 검사 전용 설치 폴더는 변경되지 않았다. 당시 맵 생성·재열기 성공은
유효하지만, 설치 불변성을 검사하지 않았으므로 고정 0.10.2.5 검증 증거로 사용하지 않는다.
업데이트 확인 창에 누가 어떻게 응답했는지는 이 기록으로 판단할 수 없다.

공식 고정 commit `761d63fca7a1663eeb7ec00c581269a2a65af5c2`의
[autoupdate.py](https://github.com/armoha/euddraft/blob/761d63fca7a1663eeb7ec00c581269a2a65af5c2/autoupdate.py)는
별도 thread에서 최신 버전을 조회하고 승인 시 다운로드한다. `atexit`에서 실행하는
배치 파일은 부모 프로세스 종료 후 설치 파일을 교체한다. 해당 소스에는 환경 변수나
명령줄을 통한 업데이트 비활성화 계약이 없다.
[msgbox.py](https://github.com/armoha/euddraft/blob/761d63fca7a1663eeb7ec00c581269a2a65af5c2/msgbox.py)는
Windows MessageBoxW로 확인 창을 띄운다.

## 구현한 방어와 한계

`SafeEudBuildPipeline`은 실행 전과 검증된 맵 승격 전에 설치를 재검사한다.
계획의 버전·실행 파일 경로·경로 출처가 다르거나 검사 실패/예외가 발생하면
`EUD_BUILD_TOOL_CHANGED`로 종료한다. 동봉 경로는 두 검사 모두 manifest 검증을
유지한다. 컴파일 성공 후 거부는 종료 코드 0을 보존하되 전체 빌드는 실패하며,
임시 작업 폴더를 정리하고 기존 출력은 변경하지 않는다.

이 방어는 업데이트 실행 자체를 차단하지 않는다. 외부 설치의 동일 버전 파일 변경,
최종 검사 이후 비동기 교체, 검사와 실행 사이 변경까지 원자적으로 막지는 못한다.
읽기 전용 설치·오프라인·자동 업데이트 차단 인수 조건은 **미완료**다.
다음 단계에서 명시적 업데이트 비활성화가 가능한 검토된 배포본/실행 격리 방식을
확정해야 한다. 임의 환경 변수나 DLL/bytecode 패치로 해결했다고 가정하지 않는다.

## 실제 스모크 조건

공식 ZIP SHA-256 `87113da1cf8ad48c7ed81ee26a9db47ae236274d74e8f0f24addf0e2ab8280b3`을
검증한 뒤 새 임시 폴더로 추출했다. 테스트 전용 `vcheckpoint.dat`에
`0.10.2.5 <현재 Unix 초>`를 기록해 upstream의 24시간 조회 간격 조건을 사용했다.
이 조건은 Shift 강제 조회로 우회되며 영구 비활성화 기능이 아니다. 앱은 사용자
설치의 checkpoint를 수정하지 않는다.

이 통제된 복사본으로 실제 빌드·MPQ/CHK 재열기가 통과했고, 설치 전체 파일의
상대 경로와 SHA-256을 실행 전후 비교해 추가·삭제·변경이 없음을 확인했다.
통합 스모크 테스트는 이제 설치 불변성도 검사한다. 게임 실행, 깨끗한 PC,
읽기 전용 설치 및 장기 업데이트 방지는 이 결과의 검증 범위가 아니다.

추가 회귀 9개와 기존 가짜 프로세스 검증을 포함한 집중 테스트 28개가 통과했다.
`flutter analyze`는 오류 없음, 전체 `flutter test`는 629개 통과·15개 skip이다.
skip 중 실제 euddraft 통합 1개는 위 별도 조건에서 통과했고 나머지 선택 환경
스모크는 이 전체 실행에서 활성화하지 않았다. 실행 SDK는 Flutter 3.47.2 /
Dart 3.13.2로 기준 3.44.8 / 3.12와 다르다. 전체 비쓰기 포맷 게이트는 기존
infrastructure 테스트 4개 차이로 실패했으며 이번 변경 파일 포맷은 통과했다.
