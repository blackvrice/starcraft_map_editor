# EUD 도구 동봉 및 다중 언어 확장 개발 계획

2026-09-15 사용자 요청으로 초안을 작성하고 2026-09-16 정리했다. **이 문서는 계획이며 동봉·Python 편집·Lua 지원이
구현됐다는 뜻이 아니다.** 기존 M6.3.1 실드·사거리·피해 유형의 실제 적용을 우선하고
M8의 패키징 기준을 재사용한다. 추정 일정 대신 단계별 완료 조건으로 진척을 판단한다.

## 1. 목표와 현재 상태

목표는 사용자가 별도 Python/euddraft 설치 없이 앱에서 EUD 맵을 빌드하고,
설정 UI·epScript·Python 및 후속 Lua 중 적절한 작성 방식을 선택하게 하는 것이다.

| 항목 | 현재 | 목표 |
| --- | --- | --- |
| 도구 제공 | 외부 euddraft 경로 선택·검증 | 검증된 도구 동봉 기본값 + 외부 경로 선택 |
| 설정 UI | 후보 5개 필드 저장·Undo·비교·공유 영향 | 검증된 필드의 결정적 생성·실제 게임 적용 |
| epScript | 기본 빌드 프로필 `.eps` | 기존 호환 유지, 생성 모듈과 사용자 코드 조합 |
| Python | 도구 내부 기반, 앱의 정식 entry 프로필은 아님 | `.py` 작성·entry·진단·안전 빌드 지원 |
| Lua | 미지원 | 버전이 명시된 EUD용 제한 문법과 변환기 |

현재 allowlist의 euddraft 0.10.2.5와 후보 eudplib 0.80.6은 최초 평가 기준이다.
최신 버전으로 자동 교체하지 않고 실제 배포물/API/게임 검증 후 지원 프로필을 확정한다.
`C:\Tools\euddraft-0.10.2.5` 부재는 준비 시 확인했지만 다른 경로의 설치 여부는 미확인이다.

## 2. 구조와 범위

앱 설치 디렉터리에 버전별 도구 패키지를 포함하고, 빌드는 기존 인터페이스 뒤의
별도 프로세스에서 실행한다. Flutter 프로세스 안에 Python을 임베드하지 않는다.
별도 프로세스는 장애·취소 경계이며 보안 샌드박스가 아니다. 사용자 Python과 플러그인은
임의 실행 코드로 취급하고 기존 실행 신뢰 정책을 유지한다.

```text
설정 UI → 선언적 설정 → 검증된 생성기 ───────┐
Lua 제한 문법 → AST/의미 검사 → 공통 중간 표현 ┤
사용자 epScript / Python entry ────────────┤
                                         ↓
                      생성 wrapper + 고정된 hook 순서
                                         ↓
                  동봉 또는 외부 euddraft (별도 프로세스)
                                         ↓
               임시 출력 → MPQ/CHK 검증 → 새 결과 맵
```

중간 표현은 타입 설정과 후속 Lua의 지원 동작을 위한 것이다. 임의 Python/epScript를
역변환하거나 모든 코드의 충돌을 정적으로 탐지한다고 약속하지 않는다. 프로젝트는
하나의 사용자 entry 언어를 선택하고 앱 생성 모듈을 조합한다. 언어 간 자유로운 상호
import/콜백은 첫 버전에서 지원하지 않는다. 기존 사용자 entry는 덮어쓰지 않는다.

### X4. Lua 기반 EUD 제한 언어

Lua 엔진으로 스크립트를 실행하는 것만으로 게임의 EUD 동작이 생성되지는 않는다.
첫 접근은 파싱 및 의미 분석으로 제한된 코드를 변환하는 것이다. 지원 버전·문법은
프로토타입 후 ADR로 확정하고, 일반 Lua 전체 호환이나 Lua VM의 맵 내 실행을 표방하지 않는다.

- [ ] Lua 문법 버전과 EUD 전용 API, 빌드 시 값/게임 중 값의 구분 명세.
- [ ] 최초 범위: 리터럴·지역 변수·검증된 EUD API 호출·제한된 조건/반복. 함수와 루프는
  종료/전개 한계와 게임 동작 의미를 검증한 범위만 허용.
- [ ] Lua의 수치·truthiness·nil·배열 인덱스와 대상 EUD 정수/조건 의미 차이를 명세.
  손실 변환은 오류로 처리하고 지원하지 않는 값은 추측해 변환하지 않음.
- [ ] AST→중간 표현→epScript 또는 Python 생성 프로토타입 비교 후 백엔드 결정.
- [ ] 원본 Lua 위치와 생성 소스 위치 매핑, 변환 오류와 컴파일 오류의 원본 행 이동.
- [ ] 파일/네트워크/프로세스 API, 임의 require, FFI, coroutine, metatable, 동적 load,
  임의 호스트 Python 호출은 첫 범위에서 거부. 사용자 코드를 변환기 내부에서 eval하지 않음.
- [ ] 입력 크기·구문 깊이·루프 전개/생성량·시간 제한, 미지원 문법 실패 테스트.
- [ ] 동일 동작의 epScript/Python/Lua 비교 fixture와 실제 컴파일·게임 검증.

최초 사용자 노출 명칭은 'Lua EUD 제한 지원'으로 하고 지원 API/문법 목록을 표시한다.
다른 언어는 어댑터 확장 지점만 준비하며 JavaScript/C#/범용 언어 구현은 이번 범위에서 제외한다.

## 4. 첫 개발 건과 진행 관리

X2는 기존 M6.3.1 생성/게임 검증 항목을 완료하는 작업으로 중복 구현하지 않는다.
M6.3.2와 런타임 M7.1은 본 계획의 언어 지원만으로 완료되지 않는다. X5는 M8의
배포 체크리스트를 보강하며 기본 맵 에디터의 남은 기능을 대체하지 않는다.

코드 변경 시 저장소 format/analyze/test 게이트와 변경 유형별 Windows/native/실제
도구 검증을 수행한다. 자동 테스트, 실제 컴파일, 게임 관찰, 배포 검증을 별도 기록한다.
현재 알려진 SDK 차이·포맷 문제·선택 스모크 미실행은 해결 전까지 릴리스 통과로 표시하지 않는다.

## 5. 근거와 확인 경계

- [euddraft 공식 저장소](https://github.com/armoha/euddraft): 별도 실행 파일 패키징 방식.
- [공식 플러그인 로더](https://github.com/armoha/euddraft/blob/master/pluginLoader.py): `.eps`/`.py` 처리 경로.
- [eudplib 라이선스](https://github.com/armoha/eudplib/blob/main/LICENSE): 본체 MIT 고지 조건.

위 링크는 앞선 검토의 근거이며 움직이는 브랜치다. X1에서 실제 동봉 버전의 태그/커밋,
배포 해시와 전체 의존성 라이선스로 고정해야 한다. Lua 관련 내용은 이 앱의 신규 설계안이며
공식 euddraft가 Lua를 직접 지원한다는 주장이 아니다.
