## 현재 확인

- 후보 5개 필드의 편집·구조 검증·프로젝트 저장·Undo, CHK 비교와 정적 공유 영향은 구현됨.
- override가 있는 프로젝트의 EUD Build는 아직 차단됨. Save As는 게임 효과를 적용하지 않음.
- `C:\Tools\euddraft-0.10.2.5`는 준비 시점에 존재하지 않음. 다른 위치의 설치 여부는 미확인.
- 후보 매니페스트는 euddraft 0.10.2.5 / eudplib 0.80.6을 기준으로 하며 runtimeUnverified 상태.
- 기존 `SafeEudBuildPipeline`은 입력/entry fingerprint, 도구 재검사, 임시 출력 및
  MPQ/CHK 검증과 출력 교체를 제공한다. 선언적 프로젝트 소스 생성은 별도 연결이 필요하다.

## 다음 실행 순서

1. 앱의 EUD 도구 설정과 사용 가능한 로컬 설치 경로를 확인한다. 설치가 필요하면 공식
   배포 출처·정확한 버전·아티팩트 해시를 검증한다. 설치 경로가 없다고 임의 버전으로
   allowlist를 바꾸지 않는다. 도구 실행 및 SC:R build와 원시 로그를 기록한다.
2. 해당 배포본의 SCData 필드 쓰기 API와 게임 시작 hook 순서를 확인한다. 사용자 entry를
   호출하는 wrapper/별도 생성 모듈 방식을 검토하고, 실행 가능한 최소 예제로 순서를
   검증한다. 소스에서 확인한 API와 실제 배포본 동작을 구분한다.
3. 자체 제작 최소 맵을 기준/변경 쌍으로 만든다. 처음에는 실드만 검증하여 무기·이동·업그레이드
   변경을 섞지 않는다. 원본 CHK와 배치 UNIT 실드 백분율을 보존하며 모든 결과는 별도 경로에 둔다.
4. 아래 관찰표를 채운 뒤 기존 CUnit 보정이 필요한지 결정한다. 현재 실드 강제 보충·클램프나
   매 프레임 쓰기는 승인된 정책으로 간주하지 않는다. 미검증 정책은 생성 대상에서 제외한다.
5. 검증된 조합만 결정적 생성기와 manifest에 연결한다. `(table, id, field)` 순서, 프로젝트/입력
   해시, 도구 및 게임 프로필, 초기화 정책과 사용자 hook 순서를 기록한다. 같은 입력은 같은
   생성 소스가 되어야 하며 사용자 entry와 임의 Python/플러그인 코드를 수정하지 않는다.
6. 기존 안전 빌드 경로로 연결한다. 빌드 시작의 맵·프로젝트 스냅샷을 고정하고 결과를 공개하기
   전에 변경 여부를 재검사한다. 반복 빌드는 직전 출력이 아닌 원본 맵에서 시작한다. 모든
   입력/출력 보호 및 프로젝트의 미지원 조합 차단을 통과한 뒤 UI Build를 활성화한다.

## 최소 실드 관찰표

각 행에 SC:R build, 입력·출력 해시, 도구 버전, 시작 직후 최대/현재 실드와 시간 경과 후
변화를 기록한다. 미관찰 값은 예상값으로 대체하지 않는다.

| 사례 | 비교 항목 |
| --- | --- |
| 기본 실드 보유 타입, 변경 없음 | 기준 맵과 변경 맵의 동일성 |
| 최대량만 변경 | CHK 기본값 사용/사용 안 함, 명시적 override 우선순위 |
| 활성만 변경 | 최대량과 활성 비트의 독립성, 원래 실드 없는 타입 |
| 활성+최대량 | 기존 배치 및 시작 hook 이후 생성 유닛 |
| 배치 실드 0/50/100% | UNIT 유효 필드 포함 여부, 시작 시 현재량 |
| 2명 이상의 소유자 | 전역 타입 설정 범위 |
| 피해·회복·재생 후 | 현재 실드 반복 덮어쓰기 여부 |
| 생산/트리거 생성·변신/모드 전환 | 생성 시점과 타입 전환 후 값 |

첫 증거는 단일 플레이 최소 사례로 얻되, 멀티플레이 검증 없이 전체 호환성을 완료로 표시하지 않는다.

## 예정 변경 지점과 테스트

- `lib/domain/eud/`: 검증된 설정 조합과 생성 명세, 결정적 출력 테스트.
- `lib/application/eud/`: 프로젝트 스냅샷 및 기존 `SafeEudBuildPipeline`과의 연결.
- `lib/infrastructure/filesystem/`: 생성 파일을 빌드 작업 공간에 기록하는 포트 구현.
- `lib/presentation/eud_editor/`: 생성 소스/실행 순서 미리보기와 지원 상태에 따른 Build 동작.
- `test/`: 같은 입력의 소스 동일성, 사용자 entry 보존, 중복/CHK 충돌, stale 결과 거부,
  반복 빌드 비누적, 실패/취소 시 원본 보존, 실제 컴파일 출력 MPQ/CHK 재검증.

구현 후 필수 format/analyze/test와 Windows 빌드·실행, 실제 euddraft 스모크를 수행한다.
SC:R 실제 관찰은 실행 가능한 환경에서 별도로 진행하고 결과를 이 문서 또는 전용 검증 문서에 남긴다.
이번 준비 작업은 소스·게임 맵·도구 설치를 변경하지 않는다.

## 준비 작업 검증 기록

문서 링크와 변경 범위를 확인했고 `flutter analyze`는 통과했다. 전체 테스트는 577개
통과·11개 skip 후 기존 `chk_unit_settings_editor_test.dart`의 9개가 `did not complete`로
종료됐다. 해당 파일 단독 재실행은 9개 모두 통과했다. 원인은 미확정이며 전체 실행이
통과했다고 간주하지 않는다. 소스 변경 없이 발생한 실행 차이이므로 구현 시작 시
전체 게이트를 다시 확인한다. 전체 비쓰기 포맷 검사는 기존 infrastructure 테스트
4개의 형식 차이로 실패했다. 이 파일들은 변경하지 않았다. 문서만 변경하여 Windows
빌드·실행은 반복하지 않았다. 실행 SDK는 Flutter 3.47.2 / Dart 3.13.2로 저장소 기준과 다르다.
