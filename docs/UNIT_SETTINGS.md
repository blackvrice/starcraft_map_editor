# 유닛 종류별 기본 설정

File → Unit Settings에서 맵 전체 유닛 종류 0~227의 사용자 이름, 최대 체력,
실드, 방어력, 생산 시간·미네랄·가스 비용을 편집한다. 무기 ID별 기본 피해량과
업그레이드당 추가 피해량도 같은 창에서 편집한다. 캔버스에 배치된 객체의
현재 체력 비율 등 개별 속성과 구분되는 설정이다.

## 입력과 적용

- 유닛과 무기를 바꿔도 입력을 유지한다. Apply는 모든 입력을 검증한 뒤 한
  명령으로 적용한다. 오류에는 대상 유닛 또는 무기 ID를 표시한다. Cancel은
  미적용 입력을 폐기한다. 객체·맵·플레이어·세력과 공유하는 Undo/Redo를 쓴다.
- 체력은 소수점을 포함한 HP로 표시하며 1/256 HP 단위까지 정확하게 저장한다.
  0~16777215.99609375 범위이고, 0.1처럼 정확하게 저장할 수 없는 값은 반올림하지
  않고 거부한다. 방어력은 0~255, 실드·비용·생산 시간·피해량은 0~65535다.
  생산 시간 입력 단위는 1/60초다. 이는 저장 필드 범위이며 게임별 유효성의
  실측 결과를 뜻하지 않는다.
- 기본값 사용 모드에서는 저장된 사용자 수치를 비활성화해 표시한다. 게임의
  기본 수치를 읽는 기능은 아직 연결되지 않았다. 기본값 선택은 플래그만 바꾸며
  기존 사용자 수치를 보존한다. Restore selected unit defaults는 선택한 유닛의
  미적용 수치·이름 입력을 폐기하고 기본값 플래그를 세운다. 다른 유닛과 무기
  입력은 유지한다. Apply/Undo로 기본값 복원을 적용하거나 되돌린다.
- 무기 피해량은 해당 무기를 공유하는 모든 유닛에 영향을 줄 수 있다. 유닛–무기
  연결은 로컬 DAT에서 읽어 직접 무기 참조와 서브유닛 경로를 구분해 표시한다.
  [목록의 지원 범위](UNIT_WEAPON_REFERENCES.md)는 주문·EUD의 추가 영향을 제외한다.
  무기는 숫자 ID로 선택하며 유닛 선택과 독립적이다. 유닛의
  기본값 복원은 공유 무기 피해량을 초기화하지 않는다.

## 무손실 편집 규칙

단일 알려진 VER가 필요하다. 59/63에서는 UNIS(4048바이트, 무기 100개),
205/206에서는 UNIx(4168바이트, 무기 130개)를 편집한다. 대상 섹션의 누락·중복·
크기 오류는 편집을 차단한다. 반대쪽 섹션이 함께 있으면 화면에 알리고 그대로
보존한다. 자동 생성, 복사, 정규화는 하지 않는다.

유닛 병렬 배열의 시작 오프셋은 기본값 플래그 0, 체력 228, 실드 1140, 방어력
1596, 시간 1824, 미네랄 2280, 가스 2736, 이름 ID 3192다. 기본 피해량은 3648,
추가 피해량은 3648 + 무기 개수 × 2에서 시작한다. 다중 바이트 수치는
little-endian이다. 선택 필드만 수정하고 미편집 값과 비표준 기존 기본값 플래그를
보존한다. 새 기본값 플래그 입력은 0/1만 허용한다.

이름은 안전한 STR 또는 STRx 하나와 유효한 UTF-8 참조가 필요하다. 변경 시 새
문자열을 추가하고 해당 유닛의 u16 ID만 교체한다. 기존 공유 문자열, 미참조 tail,
다른 유닛과 SPRP·FORC·로케이션의 참조를 보존한다. 빈 이름은 0 참조이며 NUL,
잘못된 참조·인코딩과 새 ID의 65535 초과를 거부한다. 이름 편집이 불가능해도
수치·기본값 플래그·무기 피해량은 편집할 수 있다. 오래된 문서에는 적용하지 않는다.

## 검증과 후속 범위

합성 CHK 도메인 테스트는 양쪽 버전의 정확한 바이트 수정, 경계 유닛·무기 ID,
체력 정밀도, 기본값 복원, STR/STRx의 공유 이름과 tail 보존, 오류 시 무변경을
확인한다. 위젯 테스트는 입력 취소·검증·선택 간 유지·일괄 적용·Undo/Redo·복원을
확인한다. 가짜 아카이브 gateway의 Save As/재열기로 원본 보존과 출력 바이트를
확인한다. 실제 SC:R 적용, 레거시 인코딩과 로컬 게임 기본 수치는 후속 범위다.
로컬 유닛–무기 연결 읽기는 별도 문서의 실제 설치 스모크로 검증했다.
EUD의 사거리·공격 타입 등은 M6.3.1에서 진행한다.

2026-09-09 [Staredit Network의 UNIS/UNIx 구조와 단위 설명](https://wiki.staredit.net/wiki/Scenario.chk#UNIS)을
확인했으며, 배열 구조는 [Chkdraft 고정 revision의 chk.h](https://github.com/TheNitesWhoSay/Chkdraft/blob/32d27861b16dda0b0f3d95e34bad894ea4efb2c3/src/mapping_core/chk.h)를
기준으로 대조했다. 실제 게임 실행 검증을 대신하지 않는다.

통합 설정 탭과 여러 플레이어를 지정하는 범위 복사는 후속 작업이다.
