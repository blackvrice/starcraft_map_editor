# 저장 파일 기반 EUD 빌드 준비

2026-09-16. `File → Prepare EUD Build…`에서 저장된 기준 맵, 소스 폴더,
진입 `.eps`, 새 출력 `.scx` 경로를 지정한다. 준비 성공 후 기존 Build 버튼 또는
Ctrl+B로 별도 실행한다. Prepare 자체는 컴파일·소스 저장·출력 파일 생성을 하지 않는다.

도구 경로는 이번 빌드의 선택적 override → EUD Tools 사용자 선택 → 동봉 후보 순이다.
현재 production 동봉 도구는 없다. 검사 실패 시 낮은 우선순위 도구로 전환하지 않는다.
override는 이번 메모리 내 계획에만 적용하며 EUD 프로젝트 JSON을 변경하지 않는다.

## 입력과 동작

- 모든 입력은 절대 Windows 경로다. 출력은 기준 맵과 다른 새 파일이며 소스 트리 밖이어야 한다.
- 기존 어휘적 검증과 파일 gateway의 일반 파일·canonical 경로 검사를 사용한다.
  출력이 이미 존재하면 거부하며 이 화면은 덮어쓰기 옵션을 제공하지 않는다.
- epScript와 import 코드는 컴퓨터에서 실행될 수 있으므로 사용자 신뢰 확인 후에만 준비한다.
- 현재 열린 맵/소스의 미저장 변경, untitled 소스 및 EUD 프로젝트의 미구현 설정 override가
  있으면 준비 및 앱의 Build 실행을 차단한다. 프로젝트 설정을 무시한 성공 결과를 만들지 않는다.
- 새 준비 시 기존 대기 계획을 지운다. 실패·취소 시 오래된 계획으로 Build하지 않는다.
  준비 중 중복 요청, 검사 후 선택 변경 및 편집 상태 변경도 차단한다.
- 준비가 완료되면 도구·입력·출력 경로를 계획에 고정한다. 이후 EUD Tools를 바꿔도 기존
  계획을 자동 변경하지 않는다. 새 도구를 쓰려면 다시 Prepare한다.
- 실제 Build는 안전 파이프라인의 재검사·입력 fingerprint·임시 출력·CHK 검증·출력 승격을 따른다.

화면은 현재 맵/저장 소스 경로를 제안하지만 디스크의 지정 파일을 빌드한다.
메모리의 편집 내용을 자동 저장하거나 생성하지 않는다. 준비와 실행 사이 디스크 파일은
실행 시 다시 읽으며 준비 시점의 파일 바이트를 고정하는 snapshot 기능은 아니다.
실행 중 변경 검출은 기존 파이프라인의 보장 범위다. 기본 제한 시간은 5분이다.

## 계층과 남은 작업

`EudBuildPreparationController`는 설정 컨트롤러, 설치 검사 포트, 파일 gateway,
빌드 컨트롤러를 조합한다. UI는 파일 시스템·프로세스를 직접 호출하지 않는다.
닫힌 화면의 늦은 완료가 계획을 등록하지 않도록 취소 revision을 검사한다.

이번 단계는 기존 epScript 파일 빌드 연결이다. 실드·사거리·피해 유형의 선언적 코드 생성,
Python/Lua entry, 도구 동봉, 네이티브 파일 선택 및 프로젝트 빌드 설정 영속화는 별도 작업이다.

## 검증 기록

새 컨트롤러/화면 테스트 8개가 통과했다. 도구 우선순위, 신뢰 확인, 입력/출력 오류,
기존 계획 무효화, 취소·선택/편집 상태 변경 및 컴파일 없이 준비만 하는 경계를 검증했다.
정적 분석, Windows debug 빌드와 숨김 프로세스 5초 시작 스모크도 통과했다.

공식 ZIP과 같은 해시의 별도 도구 복사본으로 실제 euddraft 스모크를 실행했다.
통합 테스트를 새 준비 컨트롤러 경유로 변경해 저장된 사용자 도구 선택 → 준비 → 빌드 →
결과 승격을 확인했다. 자체 제작 맵·최소 epScript의 원본 바이트 보존, 한글/공백 경로,
출력 MPQ/CHK 재검증과 재열기가 통과했다. 게임 실행 및 선언적 설정 적용은 미검증이다.

후속 조사에서 당시 실행 복사본의 자동 업데이트 흔적을 발견했다. 위 실행을
고정 0.10.2.5 검증으로 간주하지 않는다. 재검사 방어와 설치 전후 해시 비교를
추가한 재실행 결과 및 조건은 [자동 업데이트 조사](research/euddraft-0.10.2.5/AUTO_UPDATE_REVIEW.md)에 기록했다.

실행 SDK는 Flutter 3.47.2 / Dart 3.13.2로 기준 3.44.8 / 3.12와 다르다.
전체 비쓰기 포맷 검사는 기존 infrastructure 테스트 4개의 형식 차이로 실패했다.
해당 파일은 수정하지 않았다. 실제 Windows 화면 수동 조작은 수행하지 않았다.

전체 회귀는 첫 실행에서 기존 이름 검색 위젯 테스트 중 Flutter 내부 JIT가 종료됐고,
동일 조건 재실행은 625개 통과·10개 skip으로 완료됐다. 그 10개 중 실제 euddraft 통합
스모크 1개는 위 별도 실행에서 통과했다(전체 실행에는 helper 환경 변수를 넣지 않음).
